# PRD：Hurricane Studio macOS Storyboard UI/UX 完全重构

状态：`Draft v0.1`
日期：`2026-08-02`
视觉真源：待归档的设计师 HTML 原型
产品范围：仅 macOS Flutter 客户端 Storyboard 工作台

## 1. 背景

现有 Storyboard 工作台已经承载镜头浏览、Prompt 编辑、首尾帧与多参考模式、生成状态、参考资产、局部重绘、Seedance 上传、跨场移动、权限、保存和跨工作台同步等能力。当前目标不是局部换肤，而是在不破坏既有业务闭环的前提下，完全重构 Storyboard 的信息架构、视觉语言和交互体验。

本项目采用“纯 UI Package + 生产 Adapter”模式，确保设计师能够在不获取 Hurricane Studio 前后端源码的情况下完成 Flutter UI，同时由工程团队保留业务规则与系统安全边界。

## 2. 目标

### 2.1 用户目标

- 用户能快速理解当前项目、集、场、镜头和生成模式。
- 用户能以更低的认知成本浏览、选择和编辑大量镜头。
- 用户能清楚感知生成、保存、同步、失败和权限状态。
- 首尾帧、多参考、参考资产和视频结果在统一体验中协同工作。
- 鼠标、触控板、键盘和窗口缩放符合 macOS 桌面使用习惯。

### 2.2 交付目标

- 设计师交付独立 `storyboard_ui_v2` Flutter Package。
- UI Package 使用 Mock 数据即可完整运行和验收。
- 生产业务通过 Adapter 接入，不进入设计师代码。
- 新 UI 不遗漏经确认的现有业务能力。
- 新 UI 在视觉验收后，仍须通过真实业务回归才能进入生产。

## 3. 非目标

本次设计师交付不包含：

- 后端 API 的实现或修改。
- Riverpod Provider/Notifier 的实现。
- 用户认证、Token、租户、权限计算。
- WebSocket、SSE、任务轮询或数据库访问。
- 生产媒体鉴权、缓存和上传实现。
- 生产代码合并、发布、签名和安装包构建。
- 其他工作台的 UI/UX 重构。

如果新 UX 需要新增批量能力、改变保存语义、删除确认步骤、改变权限或增加后端字段，应作为产品变更提出，由 Hurricane 工程团队评估后再写入 Contract。

## 4. 用户和核心任务

### 4.1 主要用户

- 分镜师：浏览镜头、编辑 Prompt、生成和选择画面。
- 导演/主创：审阅镜头意图、画面和视频结果。
- 项目协作者：在权限允许范围内查看或修改指定场次。
- 只读审阅者：查看状态和结果，但不能触发写操作。

### 4.2 核心任务

1. 定位项目、集、场和目标镜头。
2. 在列表/卡片等视图中浏览镜头集合。
3. 查看镜头信息、Prompt、参考资产和媒体结果。
4. 编辑并保存图片 Prompt、视频 Prompt 或镜头描述。
5. 选择生成模式并触发单镜/批量生成。
6. 感知生成进度、成功、失败并重试。
7. 添加、移除或查看参考资产。
8. 打开统一帧编辑器，执行重绘等操作。
9. 移动镜头到其他场次，或执行组合/解组等组织操作。
10. 在只读、无权限或网络异常时获得明确反馈。

## 5. 信息架构要求

新界面具体布局以 HTML 原型为准，但必须能承载以下语义区域：

- 工作台上下文：项目、集、场、权限和同步状态。
- 工作台控制：生成模式、视图模式、筛选/批量动作。
- 镜头集合：列表、卡片或设计确认的新集合表达。
- 镜头主选区：当前镜头的核心画面和状态。
- 详情编辑区：Prompt、镜头参数、参考资产、生成结果。
- 全局反馈：加载、保存、任务、错误、只读和冲突反馈。

设计可以改变区域位置、层级和打开方式，但不能使核心能力不可发现或无状态反馈。

## 6. 必须保持的产品语义

### 6.1 上下文

- 镜头必须属于明确的项目/集/场。
- 当前场和按集浏览是不同的数据范围，不能仅靠视觉筛选假装切换。
- 镜头 ID、展示编号和业务主键不能混用。
- 跨场移动是业务写操作，必须有目标和结果反馈。

### 6.2 权限

- `editable`：允许触发 Contract 中的写操作。
- `readOnly`：允许查看，所有写入口必须禁用或隐藏并解释原因。
- `noAccess`：不得展示受限业务内容，应显示受限状态。

UI 不自行推导权限，只消费工程侧传入的权限状态。

### 6.3 生成与媒体

- 工作台主生成模式至少要兼容首尾帧与多参考模式。
- 历史关键帧 Take 必须能够正确展示和进入相应编辑路径。
- `idle` 不等于“已有结果”；UI 需依据媒体是否存在区分待生成与已出图。
- 普通生成、局部重绘和等待用户确认的重绘预览是不同状态。
- 失败必须保留错误摘要和重试入口，不能只恢复为 idle。

### 6.4 编辑与保存

- Prompt 至少包含：已同步、已修改、保存中、保存失败。
- UI 可以采用自动保存，但不得自行定义保存成功；以工程侧状态为准。
- 切换镜头时不得静默丢失未保存内容。
- 批量操作必须清楚展示范围、阻塞原因和执行反馈。

### 6.5 参考资产与结果

- 自动同步资产和用户手动选择资产需要可区分。
- 多参考模式需要展示参考数量、继承/自定义语义和视频结果。
- 媒体需要覆盖缺失、加载、就绪、失败和不可访问状态。
- 设计师只实现媒体容器和状态；生产 URL 解析、鉴权、缓存由工程侧处理。

## 7. macOS 体验要求

- 所有主要可交互元素必须有 hover、pressed、focus、disabled 状态。
- 右键菜单不可与主点击行为冲突。
- 列表或卡片需要支持键盘前后选择；实际快捷键由 Contract/工程侧确认。
- 文本编辑时不得误触工作台全局快捷键。
- 支持鼠标滚轮、触控板滚动和必要的横向滚动。
- 可调整面板必须定义最小/最大尺寸和拖拽反馈。
- 所有纯图标操作必须提供 Tooltip 或可访问标签。
- 窗口缩放不得遮挡核心保存/生成状态。
- 弹窗必须有默认焦点、取消路径和不可逆操作确认。

## 8. 组件建议

设计师可以重命名或重新组织，但必须保持可测试边界：

- `StoryboardWorkspaceV2`
- `StoryboardContextHeader`
- `StoryboardToolbar`
- `StoryboardSceneNavigator`
- `StoryboardShotCollection`
- `StoryboardShotCard`
- `StoryboardDetailPanel`
- `StoryboardPromptEditor`
- `StoryboardReferenceAssets`
- `StoryboardMediaViewer`
- `StoryboardTaskStatus`
- `StoryboardEmptyState`

- `StoryboardReadOnlyBanner`

禁止将完整工作台实现为单一巨型 Widget。

## 9. 技术方案

```text
Hurricane 生产 API / WebSocket
             ↓
Repository / API Client                 工程团队
             ↓
Riverpod Provider / Notifier            工程团队
             ↓
StoryboardWorkspaceAdapter              工程团队
             ↓
StoryboardUiState + StoryboardUiActions  双方冻结契约
             ↓
StoryboardWorkspaceV2                   设计师
```

设计师的 Package 不知道 API、Provider、Token 和生产模型。工程侧 Adapter 负责把生产状态转换为 `StoryboardUiState`，并把用户动作接回真实业务。

## 10. 质量要求

- 与冻结 HTML 原型在指定窗口尺寸下通过视觉验收。
- 所有矩阵状态在 Preview 中可主动切换和复现。
- `flutter analyze` 无 error/warning。
- Package 测试通过。
- 无网络、无后端、无登录时 Preview 可运行。
- 不输出 Token、URL、用户数据或生产日志。
- 大数据 Fixture 下滚动和选择无明显卡顿。
- UI Package 不依赖 Riverpod、HTTP、WebSocket 或 Hurricane 生产模块。
