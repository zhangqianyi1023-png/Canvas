# 视频节点截取画面帧需求文档

## 1. 文档说明

本文描述“视频节点 - 截取画面帧”功能。

这个功能的核心不是编辑视频，而是从一个视频节点中截取某一帧画面，把这一帧保存成图片素材，并在画布中生成一个新的图片节点。

一句话理解：

用户看到视频里的某一个画面很好，可以点击“截取画面帧”，系统把这一帧变成一张图片，后续可以作为图片节点继续编辑、保存到素材库、连接给下游生成节点使用。

## 2. 功能目标

### 2.1 用户目标

用户可以：

- 从视频节点中截取当前播放位置的画面。
- 从视频节点中快速截取首帧。
- 从视频节点中快速截取尾帧。
- 截取后自动生成一个图片节点。
- 图片节点保留来源视频信息。
- 截取出的图片可以继续作为普通图片使用。

### 2.2 产品目标

该功能解决三个常见场景：

- 把视频中的关键画面提取出来，作为封面或海报素材。
- 把视频的首帧/尾帧提取出来，给图生视频、视频延长、转场等能力使用。
- 把视频中的某一帧变成图片节点，再继续做打光、标注、扩图、抠图等图片工具处理。

### 2.3 设计目标

设计师需要明确：

- 按钮在视频节点工具栏中的位置。
- 点击按钮后出现什么菜单。
- 菜单里有哪些选项。
- 截取中如何展示 loading。
- 截取成功后图片节点如何出现在画布中。
- 截取失败时如何提示。

### 2.4 开发目标

开发需要明确：

- 如何读取视频当前帧。
- 如何读取首帧和尾帧。
- 如何把视频帧转成图片文件。
- 如何上传图片文件。
- 如何创建图片结果节点。
- 如何处理跨域、视频未加载、seek 失败、上传失败等问题。

## 3. 功能入口

### 3.1 入口位置

入口位于视频节点选中后的工具栏中。

工具栏按钮名称：

```text
截取画面帧
```

按钮建议使用图标按钮，hover 时显示完整 tooltip。

### 3.2 按钮状态

默认状态：

- 按钮可点击。
- hover 显示“截取画面帧”。

视频未加载完成：

- 按钮可以置灰，或点击后提示“视频尚未加载完成，请稍后重试”。

截取中：

- 按钮进入 loading 状态。
- 菜单项禁用。
- 显示进度，例如“当前帧 35%”。

视频读取失败：

- 点击后显示错误提示。

## 4. 菜单选项

点击“截取画面帧”后，出现下拉菜单。

菜单包含三个选项：

| 菜单项 | 含义 | 使用场景 |
| --- | --- | --- |
| 截取当前帧 | 截取视频当前播放头所在位置的画面 | 用户手动拖到某个想要的画面后截取 |
| 截取首帧 | 截取视频开始位置的画面 | 做视频封面、首帧参考、图生视频起始帧 |
| 截取尾帧 | 截取视频结束前的最后有效画面 | 做视频延长、尾帧参考、转场衔接 |

### 4.1 菜单交互

- 点击按钮打开菜单。
- 再次点击按钮关闭菜单。
- 点击菜单外关闭菜单。
- 按 Escape 关闭菜单。
- 点击某个菜单项后，菜单关闭并开始截取。
- 截取中不允许重复点击其他截帧项。

## 5. 截取当前帧

### 5.1 功能说明

截取当前帧，是把用户当前看到的视频画面变成图片。

当前帧由视频播放器的播放头位置决定。

### 5.2 用户流程

1. 用户选中视频节点。
2. 用户播放或拖动视频到目标画面。
3. 用户点击“截取画面帧”。
4. 用户选择“截取当前帧”。
5. 系统读取当前播放位置。
6. 系统把当前画面转成图片。
7. 系统上传图片。
8. 系统在视频节点右侧生成图片节点。

### 5.3 设计细节

截取中：

- 工具栏按钮显示 loading。
- 可以显示“当前帧 35%”之类的进度。
- 视频节点不需要遮罩整个节点，避免阻塞用户查看视频。

截取成功：

- 新图片节点自动选中。
- 原视频节点取消选中。
- 图片节点标题建议为“视频当前帧”。

截取失败：

- 显示 toast 或轻弹窗。
- 文案要让用户能理解。

失败文案示例：

```text
视频当前画面截取失败，请确认视频已加载完成后重试。
```

## 6. 截取首帧

### 6.1 功能说明

截取首帧，是把视频开始位置的画面保存为图片。

首帧时间点：

```text
0s
```

### 6.2 用户流程

1. 用户点击“截取画面帧”。
2. 用户选择“截取首帧”。
3. 系统临时跳转视频到 0s。
4. 系统读取该画面。
5. 系统上传图片。
6. 系统生成图片节点。
7. 系统恢复视频原来的播放位置。

### 6.3 设计细节

用户不应该明显感觉视频播放头被打乱。

如果系统需要临时 seek 到首帧：

- 截取完成后，应尽量恢复到用户原来的播放位置。
- 如果恢复失败，不影响截取结果，但可以不提示用户，避免制造额外干扰。

图片节点标题建议：

```text
视频首帧
```

## 7. 截取尾帧

### 7.1 功能说明

截取尾帧，是把视频结束前最后一个可读取画面保存为图片。

注意：

尾帧不一定直接取视频 duration 的精确末尾，因为很多浏览器或视频编码在最后一个时间点可能读不到画面。

建议取值：

```text
视频总时长 - 一个很小的安全偏移
```

例如：

- 视频 4 秒，可以取 3.95 秒。
- 如果视频很短，可以取总时长的一半作为偏移保护。

### 7.2 用户流程

1. 用户点击“截取画面帧”。
2. 用户选择“截取尾帧”。
3. 系统跳转到视频结束前的最后有效画面。
4. 系统读取该画面。
5. 系统上传图片。
6. 系统生成图片节点。
7. 系统恢复视频原来的播放位置。

### 7.3 设计细节

图片节点标题建议：

```text
视频尾帧
```

失败时文案：

```text
尾帧读取失败，请稍后重试，或先播放视频确认视频可以正常加载。
```

## 8. 截取成功后的图片节点

### 8.1 节点类型

截取成功后，应生成一个图片结果节点。

节点类型可以复用普通图片节点或图片结果节点。

### 8.2 节点位置

新图片节点建议出现在来源视频节点右侧。

位置规则：

- x 坐标：来源视频节点右侧 + 固定间距。
- y 坐标：与来源视频节点大致对齐。
- 如果连续截取多个帧，可以向下错开一点，避免完全重叠。

### 8.3 节点标题

根据截取类型生成标题：

| 截取类型 | 标题 |
| --- | --- |
| 当前帧 | 视频当前帧 |
| 首帧 | 视频首帧 |
| 尾帧 | 视频尾帧 |

### 8.4 节点内容

图片节点展示截取出来的图片。

图片信息需要包含：

- 图片 URL。
- 图片宽度。
- 图片高度。
- 图片比例。
- 图片来源：video-frame。
- 来源视频节点 ID。
- 来源视频 URL。
- 截取类型。
- 截取时间点。

### 8.5 节点选中

截取成功后建议：

- 新图片节点自动选中。
- 原视频节点取消选中。

这样用户能立刻看到截取结果，也能继续对图片做后续操作。

## 9. 与上游和下游的关系

### 9.1 来源关系

截取出来的图片应该记录来源视频。

建议建立关系：

- 视频节点是上游。
- 截帧图片节点是下游。

是否画连线，需要根据画布产品规则决定。

建议：

- 如果系统中的“生成结果”都会连接来源节点，则截帧图片也应自动连线。
- 如果截帧只是轻量素材操作，可以不强制连线，但数据里必须保存来源视频节点 ID。

### 9.2 给下游使用

截帧图片节点可以作为普通图片节点给下游使用。

可用于：

- 图生图。
- 图生视频首帧。
- 图生视频尾帧。
- 视频延长的尾帧参考。
- 视频封面。
- 图片扩图。
- 图片标注。
- 图片打光。
- 图片抠图。
- 素材库保存。

### 9.3 作为视频生成的首尾帧

如果下游是视频生成器，截取出来的图片可以作为：

- 首帧图。
- 尾帧图。
- 参考图。

规则建议：

- “视频首帧”默认更适合作为首帧。
- “视频尾帧”默认更适合作为尾帧。
- “视频当前帧”由用户自己选择用途。

## 10. 截取中状态

截取过程包括：

1. 读取视频元信息。
2. seek 到目标时间。
3. 把视频画面绘制到 canvas。
4. canvas 转图片文件。
5. 上传图片文件。
6. 创建图片节点。

### 10.1 进度展示

如果上传服务支持进度，按钮可显示上传进度。

示例：

```text
首帧 42%
```

如果无法拿到准确进度，可以显示：

```text
截取中...
```

### 10.2 禁用规则

截取中：

- 禁止再次点击截取菜单。
- 禁止重复提交同一种截取。
- 其他视频工具是否禁用，由产品决定；建议只禁用截帧相关操作。

### 10.3 成功反馈

成功后可以给轻提示：

```text
已截取视频画面帧
```

如果新节点自动出现且自动选中，也可以不额外提示，减少打扰。

## 11. 失败场景和提示

### 11.1 视频未加载完成

原因：

- 视频还没有 loadedmetadata。
- 视频地址不可访问。
- 视频播放器还没有准备好。

提示：

```text
视频尚未加载完成，请稍后重试。
```

### 11.2 视频尺寸无效

原因：

- videoWidth 或 videoHeight 为 0。
- 浏览器没有读取到视频画面。

提示：

```text
视频尺寸无效，无法截取画面。
```

### 11.3 seek 失败或超时

原因：

- 浏览器无法跳转到目标时间。
- 视频编码不支持准确 seek。
- 网络加载太慢。

提示：

```text
视频截帧等待超时，请重试。
```

### 11.4 canvas 转图片失败

原因：

- 视频跨域配置不正确。
- 视频资源没有允许 canvas 读取。
- 浏览器安全策略阻止读取像素。

提示：

```text
视频画面转换失败，请检查视频跨域配置。
```

给用户的普通文案可以更简单：

```text
当前视频暂时无法截取画面，请换一个视频或稍后重试。
```

开发日志里再保留详细原因。

### 11.5 图片上传失败

原因：

- 网络异常。
- 文件服务异常。
- 上传接口没有返回图片 URL。

提示：

```text
画面已截取，但上传图片失败，请重试。
```

### 11.6 来源视频节点不存在

原因：

- 截取过程中来源节点被删除。

提示：

```text
来源视频节点已不存在，无法创建截帧图片。
```

## 12. 数据结构建议

截帧图片节点建议保存以下数据：

```json
{
  "type": "result",
  "data": {
    "label": "视频当前帧",
    "resultType": "generateImage",
    "imageUrl": "截帧图片地址",
    "imageUrls": ["截帧图片地址"],
    "imageSource": "video-frame",
    "imageAssetId": "图片素材 ID",
    "sourceVideoNodeId": "来源视频节点 ID",
    "sourceVideoUrl": "来源视频地址",
    "videoFrameKind": "current",
    "videoFrameTime": 3.52,
    "imageSize": "1920×1080"
  }
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| imageSource | 固定为 video-frame，用于识别这是视频截帧 |
| sourceVideoNodeId | 来源视频节点 ID |
| sourceVideoUrl | 来源视频地址 |
| videoFrameKind | current / first / last |
| videoFrameTime | 截取时间点，单位秒 |
| imageAssetId | 上传后生成的图片素材 ID |
| imageSize | 图片宽高展示文案 |

## 13. 技术实现方案

### 13.1 前端截帧方案

基础方案：

1. 获取视频 DOM 元素。
2. 确认视频元信息已经加载。
3. 根据截取类型计算目标时间。
4. 如果是首帧或尾帧，临时 seek 到目标时间。
5. 创建 canvas。
6. canvas 尺寸设置为视频原始宽高。
7. 使用 `drawImage(video, 0, 0, width, height)` 绘制画面。
8. 使用 `canvas.toBlob()` 导出 PNG。
9. 把 PNG 上传到文件服务。
10. 用上传结果创建图片节点。

### 13.2 当前帧时间

当前帧使用视频元素的 `currentTime`。

需要注意：

- 如果 currentTime 超出视频时长，需要限制到合法范围。
- 如果当前视频暂停，也可以截取。
- 如果当前视频正在播放，截取的是执行那一刻浏览器可读取的画面。

### 13.3 首帧时间

首帧使用：

```text
0s
```

如果某些视频 0s 读取失败，可以后续兼容为：

```text
0.01s
```

### 13.4 尾帧时间

尾帧不建议直接用 duration。

建议：

```text
max(0, duration - min(0.05, duration / 2))
```

这个逻辑的意思是：

- 正常视频：取结束前 0.05 秒。
- 极短视频：避免偏移超过视频本身。

### 13.5 恢复播放位置

当用户截取首帧或尾帧时，系统会临时改变视频 currentTime。

截取完成后应尝试恢复原播放位置。

恢复失败时：

- 不影响截帧结果。
- 不需要打断用户。
- 可以记录开发日志。

## 14. 跨域和安全要求

### 14.1 为什么会有跨域问题

浏览器把视频画面画到 canvas 后，如果视频资源没有正确配置跨域，浏览器会阻止读取 canvas 像素。

普通用户可以理解为：

视频能播放，不代表一定能截帧。截帧需要浏览器有权限读取视频画面。

### 14.2 需要开发确认

开发需要确认：

- 视频 URL 是否来自同源文件服务。
- 视频资源是否有正确 CORS 响应头。
- video 标签是否设置 `crossOrigin`。
- OSS / CDN 是否允许 canvas 读取。
- 如果视频跨域不可读，是否需要后端截帧兜底。

### 14.3 后端兜底方案

如果前端无法截取，可以考虑后端截帧。

后端方案：

1. 前端提交视频 URL 和目标时间。
2. 后端使用 ffmpeg 或媒体服务截取图片。
3. 后端上传图片。
4. 返回图片 URL。
5. 前端创建图片节点。

适用情况：

- 视频跨域导致前端无法读取。
- 视频太大导致前端处理不稳定。
- 需要更准确帧级截取。
- 需要批量截取多帧。

## 15. 和视频编辑器的关系

该功能在视频节点上使用，目标是从单个视频节点提取图片。

它不是视频编辑器时间轴截帧功能。

区别：

| 能力 | 视频节点截取画面帧 | 视频编辑器时间轴截帧 |
| --- | --- | --- |
| 对象 | 单个视频节点 | 时间轴合成结果或某个轨道片段 |
| 输入 | 视频节点的视频文件 | 多轨道剪辑工程 |
| 输出 | 图片节点 | 图片节点或编辑器素材 |
| 时间来源 | 视频自身 currentTime | 时间轴 playhead |

后续可以统一底层截帧能力，但产品入口和语义不同。

## 16. 和素材库的关系

截帧后生成的图片应先成为画布图片节点。

是否自动加入素材库，有两种方案：

### 16.1 方案 A：只生成图片节点

优点：

- 行为简单。
- 不会污染素材库。
- 用户需要时再点击“添加到素材库”。

建议一期采用。

### 16.2 方案 B：同时保存到素材库

优点：

- 用户以后更容易复用。

缺点：

- 素材库可能变得很乱。
- 用户只是临时截帧时不一定想保存。

如果采用方案 B，应提供开关或明确提示。

## 17. 权限与计费

前端本地截帧本身通常不需要模型费用。

但可能涉及：

- 图片上传存储费用。
- 素材库保存费用。
- 后端 ffmpeg 截帧计算费用，如果使用后端兜底。

权限规则建议：

- 有视频查看权限，才可以截取。
- 有画布编辑权限，才可以创建截帧图片节点。
- 只读用户可以播放视频，但不能截帧生成新节点。

## 18. 埋点建议

建议记录：

- 点击“截取画面帧”按钮。
- 打开截帧菜单。
- 点击截取当前帧。
- 点击截取首帧。
- 点击截取尾帧。
- 截帧成功。
- 截帧失败。
- 上传成功。
- 上传失败。
- 截帧图片节点是否被继续连接到下游。
- 截帧图片是否被保存到素材库。

这些数据可以帮助判断：

- 用户更常截当前帧、首帧还是尾帧。
- 跨域失败是否高频。
- 截帧是否真的被用于后续创作。

## 19. 验收标准

### 19.1 入口和菜单

- 选中视频节点后，可以看到“截取画面帧”按钮。
- 点击按钮后，出现三个菜单项：截取当前帧、截取首帧、截取尾帧。
- 点击菜单外或按 Escape 可以关闭菜单。

### 19.2 截取当前帧

- 用户把视频停在某一画面后，点击“截取当前帧”。
- 系统生成图片节点。
- 图片内容与用户看到的当前画面一致。
- 图片节点记录截取时间点。

### 19.3 截取首帧

- 点击“截取首帧”后，生成图片节点。
- 图片内容为视频开头画面。
- 截取后视频播放位置尽量恢复到原位置。

### 19.4 截取尾帧

- 点击“截取尾帧”后，生成图片节点。
- 图片内容为视频结束前的有效画面。
- 截取后视频播放位置尽量恢复到原位置。

### 19.5 图片节点

- 截取成功后，新图片节点出现在视频节点右侧。
- 新图片节点自动选中。
- 图片节点可以继续使用图片工具栏。
- 图片节点可以连接到下游生成节点。
- 图片节点可以保存到素材库。

### 19.6 失败处理

- 视频未加载完成时，有明确提示。
- 视频跨域无法截帧时，有明确提示。
- 上传失败时，有明确提示。
- 失败后不会创建空图片节点。
- 失败后不会破坏原视频节点。

## 20. 后续扩展

后续可以考虑：

- 支持手动输入截取时间。
- 支持拖动时间轴选择截取点。
- 支持连续截取多帧。
- 支持每隔 N 秒自动截一帧。
- 支持截取为 JPG / PNG 可选。
- 支持截取后直接设为视频封面。
- 支持截取后直接作为图生视频首帧或尾帧。
- 支持在视频编辑器时间轴中截取合成画面。
- 支持后端精确帧截取。
- 支持批量导出视频关键帧。
