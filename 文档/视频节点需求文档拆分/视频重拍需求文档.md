# 视频重拍需求文档

## 1. 需求背景

用户在画布中生成或上传视频后，可能不想整条视频全部重做，而是只想对其中某一段进行“重新拍一遍”的处理。

这里的“视频重拍”不是现实世界里真的重新拍摄，也不是简单剪辑里的裁剪、变速或转场，而是基于原视频片段、关键帧、镜头要求和提示词，通过 AI 视频生成或视频编辑 API 生成一个新的片段，再替换回原视频时间线。

典型场景：

- 原视频整体不错，但其中某个镜头角度不满意。
- 一个商品展示片段想从正面改成侧前方。
- 一个分镜希望从中景改成特写。
- 某段镜头太平，希望加一个平滑推进或环绕。
- 原视频里某一段动作还可以，但镜头语言不符合预期。
- 用户想把一个长视频拆成多个分镜，对不同分镜设置不同镜头变化。
- 用户希望保留视频前后内容，只局部替换某个分镜。

一句话理解：

```text
视频重拍 = 选择原视频中的一个分镜片段，设置新的镜头要求，AI 生成新的片段，再把新片段替换回原视频。
```

## 2. 功能目标

为视频节点增加「视频重拍」能力。用户可以在视频节点中选择一段视频分镜，对该分镜设置镜头变化、视角、景别和补充要求，系统调用后端/API 生成新的重拍片段，并将重拍片段替换到原视频中，最终生成一个新的视频节点。

核心目标：

- 不覆盖原视频。
- 支持按分镜选择重拍范围。
- 支持将视频拆成多个分镜片段。
- 支持每个分镜单独设置镜头变化方式。
- 支持每个分镜单独设置视角、景别、补充镜头要求。
- 支持固定镜头、切换镜头、平滑移动等镜头变化方式。
- 支持生成新的重拍片段。
- 支持将重拍片段替换回原视频时间线。
- 输出一条完整的新视频。
- 新视频作为下游节点生成，并自动连接原视频节点。
- 用户可以看到任务状态、失败原因和重试入口。

## 3. 核心定义

### 3.1 什么是视频重拍

视频重拍是对原视频某一段进行 AI 重生成。

它不是：

- 不是只改播放角度。
- 不是播放器里做 3D 旋转。
- 不是简单裁剪视频。
- 不是简单缩放画面。
- 不是只给视频加滤镜。
- 不是直接把整条视频重新生成一遍。

它是：

- 从原视频中选出一个时间段。
- 提取该时间段的参考帧和视频片段。
- 将镜头需求转成 API 可理解的任务参数。
- 调用视频生成或视频编辑模型生成新的片段。
- 用新片段替换原视频中的对应片段。
- 合成输出完整视频。

### 3.2 什么是分镜

分镜是视频时间线上的一个片段。

例如一条 14.4 秒的视频，可以被切成：

```text
分镜 1：0.0s - 4.8s
分镜 2：4.8s - 9.2s
分镜 3：9.2s - 14.4s
```

每个分镜可以有自己的重拍设置。

例如：

- 分镜 1：保持不变。
- 分镜 2：固定镜头，正面，中景。
- 分镜 3：平滑移动，从侧前方特写移动到侧后方全景。

### 3.3 什么是镜头变化

镜头变化是用户希望这个分镜被如何重新拍摄。

第一版建议支持：

- 保持不变。
- 固定。
- 切换。
- 平滑移动。

这些不是直接的播放器效果，而是给 AI 视频模型和后端合成流程的生成意图。

### 3.4 什么是视角

视角描述摄像机从哪个方向看主体。

第一版建议支持：

- 正面。
- 侧前方。
- 侧后方。
- 背面。
- 俯视。
- 仰视。
- 自定义视角。

### 3.5 什么是景别

景别描述画面离主体有多近。

第一版建议支持：

- 特写。
- 中景。
- 全景。
- 远景。

### 3.6 什么是补充镜头要求

补充镜头要求是用户用自然语言描述的额外要求。

例如：

- 缓慢绕到人物侧后方。
- 镜头轻微推进，突出商品细节。
- 保持人物动作连续，不改变服装。
- 让背景保持原样，镜头只靠近主体。
- 切换到更低机位，增强冲击力。

补充镜头要求不是必填，但能帮助模型更准确理解用户意图。

## 4. 第一版能力范围

### 4.1 第一版支持

第一版支持以下能力：

- 从视频节点打开视频重拍面板。
- 展示视频时间线和缩略帧。
- 支持拖动播放头查看时间点。
- 支持将视频切分为多个分镜。
- 支持选择某个分镜。
- 支持每个分镜独立保存重拍设置。
- 支持镜头变化方式选择。
- 支持固定镜头设置。
- 支持切换镜头设置。
- 支持平滑移动镜头设置。
- 支持视角选择。
- 支持景别选择。
- 支持补充镜头要求输入。
- 支持预计积分展示。
- 支持提交生成任务。
- 支持生成处理中节点。
- 支持任务成功后生成完整新视频。
- 支持任务失败后显示失败原因。

### 4.2 第一版暂不支持

第一版不做以下能力：

- 逐帧手动调整镜头。
- 用户手动画摄像机曲线。
- 多机位复杂剪辑自动生成。
- 自动识别全部分镜并自动给建议。
- 对多个不连续片段同时重拍。
- 一次对多个分镜同时调用多个任务并自动合并。
- 重拍后手动微调模型生成片段。
- 精确控制角色骨骼动作。
- 精确保证主体 100% 一致。
- 本地模型推理。
- 音频重新生成。
- 字幕重写。
- 复杂转场生成。

这些能力可以作为后续版本扩展。

## 5. 产品原则

### 5.1 不覆盖原视频

视频重拍结果必须生成一个新视频节点。

原因：

- 用户需要保留原视频。
- 用户需要对比重拍前后效果。
- 生成失败不能破坏原素材。
- 画布逻辑应该保持可追溯。

### 5.2 优先局部重拍，不整条重生成

真实实现不建议把整条视频都提交给模型重新生成。

推荐方式：

```text
原视频片段 + 镜头要求 -> 生成重拍片段
原视频前段 + 重拍片段 + 原视频后段 -> 合成完整结果
```

原因：

- 成本更低。
- 失败影响更小。
- 速度更快。
- 更符合视频模型常见时长限制。
- 保留原视频中无需修改的部分。

### 5.3 每个分镜的设置互相独立

用户选择分镜 1 时设置为“固定”，选择分镜 2 时可以设置为“切换”，选择分镜 3 时可以设置为“平滑移动”。

不同分镜之间不能互相覆盖设置。

### 5.4 重拍不是魔法，需要让用户知道不确定性

视频重拍依赖视频生成模型。

需要在产品体验上承认这些不确定性：

- 人物一致性可能有波动。
- 物体细节可能变化。
- 背景可能轻微变化。
- 动作可能不是完全原动作。
- 片段衔接可能有轻微跳变。

产品不需要吓用户，但需要在失败、重试和结果节点信息中表达清楚。

## 6. 入口位置

### 6.1 工具栏入口

视频重拍入口位于视频节点工具栏中。

入口名称：

```text
视频重拍
```

入口图标建议：

- 场记板。
- 摄像机。
- 重拍/刷新镜头类图标。

### 6.2 显示条件

当节点满足以下条件时展示入口：

- 节点类型为视频节点。
- 节点中存在可访问的视频地址。
- 视频不是生成中。
- 视频不是上传中。
- 视频不是加载失败。
- 当前用户有权限操作该节点。

### 6.3 禁用条件

以下情况入口可以展示但禁用：

- 视频地址为空。
- 视频格式暂不支持。
- 视频时长读取失败。
- 当前任务仍在处理中。
- 用户积分不足。
- 后端视频重拍服务不可用。

禁用时 tooltip 应说明原因。

例如：

```text
视频加载完成后可使用重拍
```

或：

```text
当前视频格式暂不支持重拍
```

## 7. 用户完整流程

### 7.1 打开视频重拍面板

用户操作：

1. 用户选中一个视频节点。
2. 用户点击节点工具栏中的「视频重拍」。

系统响应：

1. 打开视频重拍面板。
2. 面板定位在视频节点附近。
3. 加载视频缩略帧。
4. 初始化默认分镜。
5. 默认选中第一个分镜。
6. 默认镜头变化为「固定」。

### 7.2 查看时间线

视频重拍面板顶部展示时间线。

用户可以：

- 查看视频缩略帧。
- 拖动播放头。
- 点击时间线定位到某个时间点。
- 查看当前选中分镜。

系统需要：

- 显示播放头时间。
- 显示分镜范围。
- 显示分镜数量。
- 当前分镜高亮。

### 7.3 裁切分镜

用户操作：

1. 用户拖动播放头到希望切分的位置。
2. 点击「裁剪」或「切分」按钮。

系统响应：

1. 判断当前播放头是否在选中分镜中间。
2. 如果太靠近分镜边缘，提示用户移动到中间一点。
3. 如果位置合法，将当前分镜拆成两个分镜。
4. 两个分镜继承合理的默认设置。
5. 时间线刷新。

示例：

原分镜：

```text
分镜 1：0.0s - 10.0s
```

在 4.0s 切分后：

```text
分镜 1：0.0s - 4.0s
分镜 2：4.0s - 10.0s
```

### 7.4 选择分镜

用户点击某个分镜卡片。

系统响应：

- 高亮该分镜。
- 播放头移动到该分镜中间。
- 右侧设置区展示该分镜自己的设置。

重要规则：

分镜设置必须跟随分镜，不是全局设置。

例如：

- 分镜 1 设置为「固定」。
- 分镜 2 设置为「切换」。
- 用户回到分镜 1 时，仍然显示「固定」。

### 7.5 设置镜头变化

用户选择镜头变化方式。

可选项：

- 保持不变。
- 固定。
- 切换。
- 平滑移动。

不同方式展示不同设置。

### 7.6 设置视角和景别

用户选择视角和景别。

系统需要保存：

- 分镜 ID。
- 镜头变化方式。
- 固定镜头或开始镜头。
- 结束镜头。
- 视角。
- 景别。
- 自定义相机参数。
- 补充镜头要求。

### 7.7 提交生成

用户点击生成按钮。

系统响应：

1. 校验视频和分镜设置。
2. 计算预计积分。
3. 创建下游处理中节点。
4. 提交任务给后端。
5. 面板可关闭，任务继续执行。
6. 任务成功后更新下游节点视频。
7. 任务失败后下游节点展示失败原因。

### 7.8 查看结果

任务成功后：

- 画布中出现「视频重拍」结果节点。
- 节点连接到原视频节点。
- 结果节点中展示完整合成后的视频。
- 用户可以播放、下载、继续编辑、继续重拍。

## 8. 面板布局

### 8.1 面板整体

视频重拍面板建议为浮层面板。

结构：

```text
顶部：分镜标题 + 工具按钮
中部：视频缩略时间线 + 分镜列表
设置区：镜头变化 + 视角/景别 + 3D 相机控件 + 补充要求
底部：积分 + 状态 + 生成按钮
```

### 8.2 顶部区域

顶部显示：

- 当前分镜标题。
- 当前分镜时间范围。
- 功能名称「视频重拍」。
- 播放/预览按钮，可选。
- 分镜切分按钮。
- 重置按钮。
- 关闭按钮。

示例：

```text
分镜 1/3 0.0s-4.8s  视频重拍
```

### 8.3 时间线区域

时间线区域包括：

- 缩略帧胶片条。
- 播放头。
- 播放头时间。
- 分镜轨道。
- 分镜卡片。

缩略帧胶片条：

- 展示视频不同时间点画面。
- 不要求每一帧都展示。
- 可以每隔固定时间抽帧。

播放头：

- 可拖动。
- 显示当前时间。
- 支持键盘左右微调。

分镜轨道：

- 展示所有分镜。
- 当前分镜高亮。
- 分镜上显示时间范围和镜头变化方式。

### 8.4 镜头变化区域

展示四个选项：

- 保持不变。
- 固定。
- 切换。
- 平滑移动。

建议使用横向分段按钮。

选中态需要明显。

### 8.5 3D 相机控件区域

左侧建议展示 3D 相机控件。

这个控件的作用：

- 帮助用户直观理解视角。
- 让用户拖动摄像机方向。
- 显示主体参考平面或预览图。
- 展示当前镜头从哪个方向看主体。

注意：

这不代表系统真的有完整 3D 场景。

它是一个“镜头意图控制器”，最终会转换成提示词和参数给 API。

### 8.6 右侧设置区域

右侧展示：

- 视角选项。
- 景别选项。
- 补充镜头要求输入框。

当镜头变化为「切换」或「平滑移动」时，还需要展示：

- 开始镜头。
- 结束镜头。

用户可以分别设置开始镜头和结束镜头。

### 8.7 底部区域

底部展示：

- 状态文案。
- 预计积分。
- 生成按钮。

状态文案示例：

- 已拆分为两个分镜片段。
- 请把指针移动到分镜中间一点再裁剪。
- 当前分镜保持原视频，不做镜头变化。
- 正在提交重拍任务。
- 任务已提交。

## 9. 镜头变化方式

### 9.1 保持不变

含义：

该分镜不进行重拍，最终合成时沿用原视频片段。

适用场景：

- 用户只想切分结构。
- 某些片段不需要改。
- 用户只重拍其中一段。

界面表现：

- 视角、景别、补充要求禁用。
- 3D 相机控件禁用或弱化。
- 提示“当前分镜会沿用原片段”。

技术处理：

- 不调用视频生成 API。
- 合成时直接使用原视频对应片段。

### 9.2 固定

含义：

该分镜使用一个固定镜头重新生成。

用户需要设置：

- 视角。
- 景别。
- 补充镜头要求，可选。

适用场景：

- 把镜头改成正面。
- 把镜头改成侧前方。
- 把全景改成特写。
- 保持画面稳定，不需要运镜。

技术处理：

- 提取该分镜视频片段。
- 提取代表帧。
- 将固定镜头参数转为 prompt。
- 调用视频生成/编辑 API 生成新片段。

### 9.3 切换

含义：

该分镜中发生一次明显镜头切换。

例如：

- 前半段保持正面。
- 后半段切到侧面。
- 从中景切到特写。

用户需要设置：

- 开始镜头。
- 结束镜头。
- 补充镜头要求，可选。

适用场景：

- 希望有剪辑感。
- 希望从一个视角切到另一个视角。
- 希望强调某个动作或商品细节。

技术处理有两种可选方案：

方案 A：单次 API 生成完整切换片段。

```text
原片段 + 开始镜头 + 结束镜头 + 切换要求 -> 新片段
```

优点：

- 一次任务完成。
- 接口简单。

缺点：

- 模型未必能稳定在中间完成“切换”。

方案 B：拆成两个子片段生成，再合并。

```text
子片段 1：开始镜头
子片段 2：结束镜头
合成：子片段 1 + 子片段 2
```

优点：

- 更可控。

缺点：

- 任务更复杂。
- 衔接点可能跳。

第一版建议优先用方案 A，除非 API 明确不支持镜头切换描述。

### 9.4 平滑移动

含义：

镜头从开始位置连续移动到结束位置。

例如：

- 从正面特写平滑移动到侧前方中景。
- 从全景慢慢推进到商品特写。
- 从侧面平滑绕到人物侧后方。

用户需要设置：

- 开始镜头。
- 结束镜头。
- 补充镜头要求。

平滑移动必须有开始镜头和结束镜头。

不能只设置一个“移动”选项。

技术处理：

- 将开始镜头和结束镜头转换为镜头路径描述。
- 提交给支持运镜或视频生成的 API。
- 如果 API 不支持结构化摄像机参数，则把参数翻译为自然语言 prompt。

## 10. 视角设置

### 10.1 预设视角

第一版建议支持：

- 正面。
- 侧前方。
- 侧后方。
- 背面。
- 俯视。
- 仰视。

每个预设对应一组内部参数。

示例：

```json
{
  "angle": "侧前方",
  "yaw": -35,
  "pitch": 0
}
```

### 10.2 自定义视角

用户通过 3D 控件拖动摄像机位置后，系统进入自定义视角。

需要保存：

- yaw，水平角度。
- pitch，垂直角度。
- distance，距离。
- shotSize，景别。

示例：

```json
{
  "angle": "自定义视角",
  "custom": true,
  "yaw": -22,
  "pitch": 8,
  "distance": 3.2,
  "shotSize": "中景"
}
```

### 10.3 视角给 AI 的方式

视角参数不是直接控制真实摄像机。

正式实现中应把它转换成：

- API 支持的结构化参数，如果 API 支持。
- 自然语言提示词，如果 API 不支持结构化镜头参数。

例如：

```text
将当前片段重拍为侧前方中景，摄像机从人物左前方约 35 度观察主体，保持原场景、服装、动作和视频风格一致。
```

## 11. 景别设置

### 11.1 景别选项

第一版建议支持：

- 特写。
- 中景。
- 全景。
- 远景。

### 11.2 景别含义

特写：

- 主体占画面比例大。
- 适合强调脸部、商品细节、手部动作。

中景：

- 主体和环境都有一定展示。
- 适合常规人物动作、商品展示。

全景：

- 展示主体整体和较多环境。
- 适合场景说明。

远景：

- 主体较小，环境占比更大。
- 适合建立空间感。

### 11.3 景别给 AI 的方式

景别应转换为 prompt 或 API 参数。

例如：

```text
使用特写镜头，主体占画面主要区域，突出商品纹理和细节。
```

或：

```json
{
  "shot_size": "close_up"
}
```

具体字段以实际 API 为准。

## 14. 推荐技术实现方案

### 14.1 总体流程

推荐真实实现流程：

```text
1. 用户选择分镜
2. 前端提交重拍任务
3. 后端下载或读取原视频
4. 后端裁剪目标分镜片段
5. 后端提取关键帧
6. 后端构造 API 请求
7. API 生成重拍片段
8. 后端检查片段时长、分辨率、帧率
9. 后端将重拍片段替换回原视频时间线
10. 后端输出完整视频
11. 前端更新下游结果节点
```

### 14.2 后端裁剪

后端需要使用视频处理工具裁剪原片段。

建议使用：

- FFmpeg。

裁剪内容：

- 目标分镜视频片段。
- 目标分镜首帧。
- 目标分镜尾帧。
- 可选：目标分镜中间帧。

这些素材用于给视频生成模型提供上下文。

### 14.3 API 生成重拍片段

后端调用视频生成或视频编辑 API。

可能输入：

- 原片段。
- 首帧。
- 尾帧。
- 中间参考帧。
- 镜头变化方式。
- 视角。
- 景别。
- 补充提示词。
- 原视频内容分析摘要。

输出：

- 新的重拍片段视频。

### 14.4 片段时长处理

重拍片段时长可能和原分镜不完全一致。

第一版建议：

- 尽量请求 API 输出与原分镜相同时长。
- 如果差异很小，可以通过轻微变速对齐。
- 如果差异较大，任务标记为需要处理或失败。

处理策略：

```text
原分镜 4.0s，新片段 4.1s -> 可轻微变速到 4.0s
原分镜 4.0s，新片段 6.0s -> 不建议强行变速，应失败或提示重新生成
```

### 14.5 分辨率和帧率处理

重拍片段需要与原视频统一：

- 分辨率。
- 帧率。
- 编码格式。
- 色彩空间。
- 音频轨道。

后端合成前需要转码规范化。

### 14.6 替换合成

合成方式：

```text
原视频 0 - start
+ 重拍片段
+ 原视频 end - 结尾
= 完整重拍后视频
```

如果多个分镜未来支持同时重拍，则按时间顺序替换。

第一版建议只提交一个分镜重拍，或虽然展示多个分镜设置，但一次生成以当前选中分镜为主。

### 14.7 音频处理

音频是重拍功能的重点边界。

第一版推荐：

- 默认沿用原视频音频。
- 重拍片段对应时间段继续使用原音频。
- 不生成新音频。
- 不自动重写字幕。

原因：

- 镜头重拍主要是画面变化。
- 音频重新生成会增加复杂度。
- 原音频通常可以保持视频连续。

风险：

- 如果重拍画面动作变化很大，原音频可能不匹配。

后续版本可以支持：

- 静音重拍片段。
- 自动生成环境音。
- 自动重配音。
- 保留背景音乐但移除原人声。

## 15. API 能力假设

### 15.1 最理想 API

最理想的 API 支持：

- 输入原视频片段。
- 输入首尾帧。
- 输入参考提示词。
- 输入目标时长。
- 输入镜头运动描述。
- 输出指定时长视频。

这种情况下，视频重拍可以比较直接实现。

### 15.2 常见可行 API

很多视频模型可能不支持真正的视频编辑，而是支持：

- 图生视频。
- 首尾帧生成视频。
- 视频参考生成视频。
- 文生视频。

这种情况下，重拍可通过以下方式变通：

- 用分镜首帧作为起始参考。
- 用分镜尾帧作为结束参考。
- 用原片段作为内容参考。
- 用 prompt 描述镜头变化。
- 生成新片段。

### 15.3 如果 API 不支持视频输入

如果 API 只支持图生视频：

可以使用：

- 分镜首帧。
- 分镜尾帧。
- 中间关键帧。
- 原视频分析摘要。
- 提示词。

但效果会更不稳定。

需要在产品中降低预期。

### 15.4 如果 API 支持视频到视频

如果 API 支持 video-to-video 或视频编辑：

推荐优先使用。

因为它更有机会保持：

- 原主体。
- 原动作。
- 原场景。
- 原风格。

## 16. Prompt 生成规则

### 16.1 Prompt 组成

提交给 API 的 prompt 建议由系统自动拼接。

组成：

- 原视频内容摘要。
- 当前分镜时间范围。
- 镜头变化方式。
- 开始视角。
- 结束视角。
- 景别。
- 用户补充要求。
- 保持一致性约束。

### 16.2 固定镜头 Prompt 示例

```text
请基于原视频片段进行重拍，保持原主体、服装、场景、动作节奏和整体风格一致。
将镜头调整为正面中景，画面稳定，不做明显运镜。
用户补充要求：突出商品展示，保持背景不变。
```

### 16.3 切换镜头 Prompt 示例

```text
请基于原视频片段进行重拍，保持原主体、场景和动作连续。
镜头从正面中景切换到侧前方特写，形成一次自然的镜头切换。
切换后突出主体细节，不改变原视频风格。
```

### 16.4 平滑移动 Prompt 示例

```text
请基于原视频片段进行重拍，保持原主体、服装、场景、动作和光线一致。
镜头从正面特写开始，平滑移动到侧前方中景。
运动应该缓慢、稳定、自然，像摄像机围绕主体轻微移动。
用户补充要求：保持动作连续，不要改变背景布局。
```

### 16.5 一致性约束

建议自动加入：

```text
保持人物身份一致，保持服装、商品、场景、光线、色彩风格一致，不要新增无关物体，不要改变视频主体动作意图。
```

## 17. 画布节点规则

### 17.1 生成新节点

视频重拍结果必须生成新节点。

节点标题：

```text
视频重拍
```

节点类型：

```text
视频结果节点
```

### 17.2 节点位置

新节点建议出现在原视频节点右侧或右下方。

如果原位置已有节点，则自动寻找空位。

### 17.3 连线关系

自动创建连线：

```text
原视频节点 -> 视频重拍结果节点
```

### 17.4 节点状态

新节点需要支持：

- 处理中。
- 成功。
- 失败。
- 可重试。

### 17.5 节点数据

结果节点建议保存：

```json
{
  "operation": "video-retake",
  "sourceVideoUrl": "/uploads/source.mp4",
  "resultVideoUrl": "/uploads/retake-result.mp4",
  "segment": {
    "start": 4.8,
    "end": 9.2
  },
  "retake": {
    "mode": "平滑移动",
    "cameraStart": {},
    "cameraEnd": {},

  },

}
```

## 18. 积分和成本

### 18.1 积分展示

面板底部展示预计消耗积分。

积分应该根据：

- 分镜时长。
- 镜头变化方式。
- 是否需要生成新片段。
- 模型成本。
- 是否需要后端合成。

### 18.2 保持不变不应收费

如果当前分镜为“保持不变”，不调用 API，不应按重拍收费。

如果用户只是保存分镜结构，也不应收费。

### 18.3 固定、切换、平滑移动成本

建议成本从低到高：

```text
固定 < 切换 < 平滑移动
```

原因：

- 固定镜头意图最简单。
- 切换需要理解两个镜头。
- 平滑移动需要生成连续运镜，难度最高。

### 18.4 扣费时机

建议：

- 任务成功提交后锁定积分。
- 任务失败后按平台规则退还或不扣。
- 如果 API 已实际消耗，则需要明确失败扣费规则。

这一点需要和计费系统统一。

## 19. 状态和反馈

### 19.1 面板内状态

面板内展示轻量状态：

- 已拆分分镜。
- 已重置设置。
- 正在提交任务。
- 任务已提交。
- 提交失败。

### 19.2 节点状态

下游节点展示任务状态：

- 等待处理。
- 生成重拍片段中。
- 合成完整视频中。
- 保存结果中。
- 完成。
- 失败。

### 19.3 失败原因

失败时需要展示可读原因。

例如：

- 视频裁剪失败。
- 当前视频格式不支持。
- API 生成失败。
- 生成片段时长异常。
- 视频合成失败。
- 积分不足。
- 网络错误。

### 19.4 重试

失败节点应提供重试入口。

重试时：

- 沿用上次参数。
- 允许用户回到原视频节点修改参数后重新提交。

## 20. 边界场景

### 20.1 视频太短

如果视频太短，不适合切分。

建议：

- 仍允许整体重拍。
- 禁止切分过短分镜。
- 最小分镜时长建议 1.0s 或 1.2s。

### 20.2 分镜太短

如果分镜时长过短：

- 不允许再次切分。
- 可以提示“当前分镜太短，暂不再拆分”。

### 20.3 播放头靠近边缘

如果播放头距离分镜开始或结束太近：

- 不允许切分。
- 提示“请把指针移动到分镜中间一点再裁剪”。

### 20.4 视频读取失败

如果无法读取视频时长：

- 面板不进入可编辑状态。
- 提示用户重新上传或检查视频。

### 20.5 视频跨域不可读取

如果前端无法抽帧：

- 仍可提交后端处理。
- 缩略帧可使用占位。
- 后端负责读取视频。

### 20.6 生成片段和原片段不连续

如果模型输出和原视频衔接明显跳变：

- 第一版不做自动修复。
- 可以提供重新生成。
- 后续可增加过渡帧或交叉淡入淡出。

### 20.7 API 不支持目标时长

如果 API 只能生成固定时长：

- 后端需要裁剪或变速。
- 如果无法合理对齐，应提示失败。

## 21. 技术风险

### 21.1 主体一致性风险

AI 生成的新片段可能改变人物、商品或场景细节。

缓解方式：

- 输入原片段。
- 输入关键帧。
- 加入一致性 prompt。
- 使用支持视频参考的模型。

### 21.2 动作连续性风险

新片段动作可能与前后片段不连续。

缓解方式：

- 使用首尾帧约束。
- 使用原片段作为视频参考。
- 要求输出时长一致。
- 合成前检查首尾帧差异。

### 21.3 运镜可控性风险

用户设置的“平滑移动”不一定被模型严格执行。

缓解方式：

- 将镜头参数翻译成更清楚的自然语言。
- 限制第一版运镜选项数量。
- 给用户重新生成机会。

### 21.4 合成风险

合成时可能出现：

- 分辨率不一致。
- 帧率不一致。
- 编码不一致。
- 音画不同步。

缓解方式：

- 后端统一转码。
- 使用同一输出编码规格。
- 合成后做基本校验。

## 22. 后端任务阶段

建议任务拆成以下阶段：

```text
pending：等待处理
prepare：准备素材
cutting：裁剪原片段
generating：生成重拍片段
normalizing：规范化片段
compositing：合成完整视频
saving：保存结果
success：完成
failed：失败
```

前端可以映射为更易懂的文案：

- 正在准备视频。
- 正在生成重拍片段。
- 正在合成完整视频。
- 正在保存结果。
- 生成完成。
- 生成失败。

## 23. 设计验收清单

设计侧需要确认：

- 视频重拍入口在视频节点工具栏中清晰可见。
- 面板顶部能看出当前分镜和时间范围。
- 时间线缩略帧清晰。
- 播放头明显且可拖动。
- 当前分镜高亮。
- 切分后的多个分镜容易区分。
- 镜头变化方式选项清楚。
- 不同镜头变化方式下，设置区内容正确变化。
- 固定模式只展示一个镜头设置。
- 切换模式展示开始镜头和结束镜头。
- 平滑移动模式展示开始镜头和结束镜头。
- 3D 相机控件能表达视角。
- 视角和景别按钮尺寸合理。
- 补充镜头要求输入框清楚。
- 积分和生成按钮位置明确。
- 失败状态有清晰说明。

## 24. 开发验收标准

开发侧需要满足：

- 只有有效视频节点展示视频重拍入口。
- 点击入口能打开视频重拍面板。
- 面板能读取视频时长。
- 时间线能展示缩略帧或占位。
- 播放头能拖动。
- 分镜能切分。
- 分镜不能切得过短。
- 选择分镜后能加载该分镜设置。
- 每个分镜设置互相独立。
- 固定模式能保存一个镜头设置。
- 切换模式能保存开始镜头和结束镜头。
- 平滑移动模式能保存开始镜头和结束镜头。
- 生成时能创建下游处理中节点。
- 后端任务成功后更新结果节点。
- 后端任务失败后结果节点显示失败。
- 原视频节点不被覆盖。
- 新节点自动连接原视频节点。
- 任务参数中包含分镜时间范围和镜头设置。
- 合成输出是完整视频，不是单独片段。

## 25. 测试用例建议

### 25.1 打开面板

步骤：

1. 选中一个有效视频节点。
2. 点击「视频重拍」。

预期：

- 打开视频重拍面板。
- 默认展示一个分镜。
- 默认选中第一个分镜。

### 25.2 切分分镜

步骤：

1. 拖动播放头到中间。
2. 点击裁剪。

预期：

- 当前分镜被拆成两个。
- 时间范围正确。
- 当前选中分镜更新。

### 25.3 分镜设置独立

步骤：

1. 分镜 1 设置为固定。
2. 分镜 2 设置为切换。
3. 回到分镜 1。

预期：

- 分镜 1 仍显示固定。
- 分镜 2 的设置没有覆盖分镜 1。

### 25.4 平滑移动镜头

步骤：

1. 选择平滑移动。
2. 设置开始镜头为正面特写。
3. 设置结束镜头为侧前方中景。

预期：

- 两组镜头设置都保存。
- 提交参数包含开始镜头和结束镜头。

### 25.5 保持不变

步骤：

1. 选择保持不变。

预期：

- 视角和景别设置禁用。
- 提示当前分镜沿用原视频。
- 提交时该分镜不调用重拍 API。

### 25.6 提交任务

步骤：

1. 设置某个分镜为固定。
2. 点击生成。

预期：

- 创建下游处理中节点。
- 提交任务包含原视频地址、分镜时间、镜头设置。
- 原节点不被覆盖。

### 25.7 任务成功

步骤：

1. 后端返回成功结果。

预期：

- 下游节点更新为完整视频。
- 可以播放。
- 节点标题为视频重拍。

### 25.8 任务失败

步骤：

1. 后端返回失败。

预期：

- 下游节点显示失败。
- 展示失败原因。
- 提供重试入口。

## 26. 后续扩展

### 26.1 多分镜批量重拍

后续可以支持一次选择多个分镜重拍。

系统按时间顺序生成多个片段，再统一合成。

### 26.2 自动分镜识别

后续可以自动识别镜头切点，自动切分分镜。

用户可以在自动切分基础上微调。

### 26.3 分镜推荐镜头

系统可以根据视频内容推荐：

- 哪些片段适合特写。
- 哪些片段适合推进。
- 哪些片段适合切换。

### 26.4 重拍结果对比

可以支持：

- 原片段和重拍片段并排对比。
- A/B 播放。
- 一键回退。

### 26.5 音频重构

后续可以支持：

- 保留背景音乐。
- 重新生成环境音。
- 自动配音。
- 音画同步校正。

### 26.6 更专业的运镜控制

后续可以支持：

- 推镜。
- 拉镜。
- 横移。
- 环绕。
- 跟拍。
- 手持感。
- 稳定器感。

这些可以作为平滑移动的子选项。

## 27. 一句话总结

视频重拍的正式实现应是“分镜级 AI 重生成 + 后端替换合成”，不是简单复用原视频，也不是整条视频重新生成。用户在界面上选择某个分镜，设置镜头变化、视角、景别和补充要求；系统生成新的重拍片段，再把它替换回原视频时间线，最终输出一个新的完整视频节点。
