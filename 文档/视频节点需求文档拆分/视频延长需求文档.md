# 视频延长需求文档

## 1. 需求背景

用户在画布中生成或上传视频后，可能希望在原视频基础上继续延长内容。例如：

- 广告视频结尾想继续展示商品细节。
- 人物动作还没结束，希望继续自然完成动作。
- 镜头正在推进，希望继续保持运镜。
- 当前视频太短，希望补充片头或片尾。
- 希望基于原视频风格继续生成新的场景推进片段。

视频延长不是简单地把原视频重生成得更长，而是基于原视频的首帧、尾帧、参考片段和提示词，生成一段新增视频片段，再由后端将新增片段与原视频拼接，得到完整延长后的视频。

## 2. 功能目标

为视频节点增加「视频延长」能力。用户可以选择从片头或片尾延长视频，选择延长时长和延长方式，系统调用视频生成 API 生成新增片段，并将新增片段与原视频合成为一个新的完整视频节点。

核心目标：

- 不覆盖原视频。
- 生成一个新的延长后视频节点。
- 支持片尾延长和片头延长。
- 支持选择延长时长。
- 支持选择延长方式。
- 支持用户输入提示词，描述希望延长出的画面、动作或运镜。
- 尽量保持原视频的主体、场景、风格、光线、动作和运镜连续。
- 避免让视频模型直接输出完整长视频，由后端负责拼接。

## 3. 核心原则

视频延长的正式方案应采用：

```text
原视频 + 新增延长片段 = 延长后完整视频
```

不建议采用：

```text
让模型直接输出原视频 + 延长片段的完整长视频
```

原因：

- 多数视频生成模型存在最大输出时长限制。
- Seedance 2.0 这类模型通常更适合作为新增片段生成模型，而不是完整长视频合成器。
- 如果原视频已经接近模型最大时长，再要求模型输出更长完整视频，失败率高、成本高、不可控。
- 只生成新增片段可以降低成本、降低失败影响，并便于后端拼接和排查问题。

因此，第一版应明确：

- 模型只负责生成新增延长片段。
- 后端负责拼接、转码、音频处理和输出完整结果。

## 4. 第一版能力范围

第一版支持：

- 片尾延长。
- 片头延长。
- 延长时长选择。
- 延长方式选择。
- 用户提示词输入。
- 可选参考素材输入。
- 生成新增延长片段。
- 后端将新增片段与原视频拼接。
- 生成新的完整视频节点。

第一版暂不支持：

- 多段连续自动延长。
- 一次延长超过模型最大支持时长。
- 用户逐帧编辑衔接点。
- 手动调整拼接过渡帧。
- 自动生成复杂分镜脚本。
- 对整条长视频重新生成。
- 本地模型推理。

## 5. 延长方向

### 5.1 片尾延长

片尾延长是在原视频结尾继续生成内容。

处理方式：

```text
原视频 + 新增片尾片段 = 延长后完整视频
```

建议输入：

- 原视频。
- 原视频尾帧。
- 原视频最后 1-2 秒参考片段。
- 视频内容分析结果。
- 用户提示词。
- 延长方式。
- 延长时长。
- 可选参考素材。

适用场景：

- 视频结尾动作还未完成。
- 商品展示还想继续推进。
- 镜头运动正在继续。
- 希望自然补充结尾内容。

### 5.2 片头延长

片头延长是在原视频开头之前补充内容。

处理方式：

```text
新增片头片段 + 原视频 = 延长后完整视频
```

建议输入：

- 原视频。
- 原视频首帧。
- 原视频开头 1-2 秒参考片段。
- 视频内容分析结果。
- 用户提示词。
- 延长方式。
- 延长时长。
- 可选参考素材。

适用场景：

- 视频开头太突兀。
- 需要补充进入场景的镜头。
- 需要增加铺垫或开场动作。
- 希望让视频开头更完整。

片头延长通常比片尾延长更难，因为它需要生成一段能自然衔接到原视频首帧之前的内容。第一版可以支持片头延长，但需要在产品和技术评估中明确其效果更依赖模型能力。

## 6. 延长方式

延长方式用于告诉模型优先保持什么连续性。

### 6.1 自然延续

默认选项。

目标：

- 保持原视频画面、主体、场景、光线、色彩和节奏。
- 让画面自然继续发展。
- 不主动推进剧情或大幅改变镜头。

适合：

- 大多数普通视频。
- 商品展示。
- 环境镜头。
- 简单人物动作。

### 6.2 动作延续

目标：

- 重点延续主体动作。
- 保持人物动作、手部动作、商品运动、液体流动、物体旋转等连续。

适合：

- 人物正在运动。
- 手正在操作物体。
- 商品正在旋转。
- 物体正在移动。

### 6.3 运镜延续

目标：

- 重点延续镜头运动。
- 保持推进、拉远、横移、环绕、俯仰、手持感等镜头趋势。

适合：

- 镜头运动明显的视频。
- 产品环绕镜头。
- 推进特写镜头。
- 横移展示镜头。

### 6.4 场景推进

目标：

- 不只是自然继续，而是让内容进入下一步。
- 可以让视频从当前状态推进到后续动作、后续场景或后续展示重点。

适合：

- 广告短片。
- 分镜创作。
- 商品演示。
- 人物动作需要进入下一阶段。

示例：

- 从商品整体展示推进到细节特写。
- 从人物准备动作推进到完成动作。
- 从场景铺垫推进到产品出现。

## 7. 用户流程

1. 用户选中一个视频节点。
2. 用户点击节点工具栏中的「视频延长」。
3. 系统打开视频延长面板。
4. 用户选择延长方向：片尾延长或片头延长。
5. 用户选择延长时长。
6. 用户选择延长方式。
7. 用户输入提示词，描述希望延长出的画面、动作或运镜。
8. 用户可选上传或引用参考素材。
9. 用户点击生成。
10. 系统提交视频延长任务。
11. 后端提取首帧或尾帧，以及对应的 1-2 秒参考片段。
12. 后端调用视频生成 API 生成新增延长片段。
13. 后端将新增片段与原视频拼接。
14. 画布中生成一个新的完整延长后视频节点。
15. 新节点自动连接到原视频节点。

## 8. 输入素材

### 8.1 必要输入

片尾延长：

- 原视频。
- 原视频尾帧。
- 原视频最后 1-2 秒参考片段。
- 延长方向。
- 延长时长。
- 延长方式。

片头延长：

- 原视频。
- 原视频首帧。
- 原视频开头 1-2 秒参考片段。
- 延长方向。
- 延长时长。
- 延长方式。

### 8.2 可选输入

- 用户提示词。
- 参考图片。
- 参考视频。
- 画布中已有素材。

参考素材用于帮助模型理解主体、风格、场景或动作方向，但不能替代原视频首尾帧和参考片段。

## 9. 自动分析要求

为了让延长片段更自然，系统建议在生成前对原视频进行自动分析。

分析内容包括：

- 主体是什么。
- 场景是什么。
- 当前动作状态。
- 当前镜头运动。
- 光线和色彩风格。
- 画面比例和构图。
- 是否有人物、商品、文字、Logo。
- 片头/片尾处的动作趋势。

分析结果应转化为内置提示词，与用户提示词一起发送给视频生成 API。

示例内置提示词结构：

```text
请基于原视频的画面风格、主体、动作和镜头运动生成延长片段。
保持主体一致、场景一致、光线一致、色彩一致、镜头语言一致。
延长方向：片尾延长。
延长方式：动作延续。
原视频尾帧中主体正在向右转身，请继续完成该动作。
不要切换场景，不要新增无关主体，不要改变主体身份。
```

## 10. 视频生成 API 使用策略

正式版本建议将视频生成模型用于生成新增延长片段。

如果使用 Seedance 2.0 或类似模型，需要确认以下能力：

- 是否支持图生视频。
- 是否支持视频参考输入。
- 是否支持首帧或尾帧作为约束。
- 是否支持参考视频。
- 是否支持设定生成时长。
- 是否支持返回尾帧。
- 是否支持指定分辨率、比例和模型版本。
- 最大输出时长是多少。

主策略：

- 片尾延长：以尾帧作为起始画面约束，结合最后 1-2 秒参考片段生成新增片段。
- 片头延长：以首帧作为衔接目标，结合开头 1-2 秒参考片段生成前置片段。

如果 API 不支持直接使用「尾帧作为起始帧」或「首帧作为结束帧」，则需要降级为普通图生视频或参考视频生成，但需要明确效果风险。

## 11. 后端拼接要求

后端需要负责将原视频与新增片段合成为完整视频。

片尾延长：

```text
完整结果 = 原视频 + 新增片尾片段
```

片头延长：

```text
完整结果 = 新增片头片段 + 原视频
```

拼接时需要处理：

- 分辨率统一。
- 帧率统一。
- 编码格式统一。
- 色彩空间尽量一致。
- 音频轨处理。
- 视频时长元数据修正。
- 文件封装格式统一。

可选优化：

- 拼接点增加 3-8 帧轻微过渡。
- 对新增片段做色彩匹配。
- 对新增片段做轻微稳定处理。
- 如果无音频，延长片段保持静音。
- 如果原视频有背景音乐，需要决定是否延续、淡出或保持原音频。

## 12. 音频处理

第一版需要明确音频策略。

建议第一版采用简单策略：

- 原视频音频保持不变。
- 新增片段默认静音，或使用模型返回音频。
- 如果新增片段无音频，拼接后新增段静音。
- 如果原视频有背景音乐，后续版本再考虑音乐延展。

可选增强策略：

- 对原视频末尾音频做淡出。
- 给新增片段补充环境音或背景音乐。
- 使用音频生成模型延长音乐。
- 使用 TTS 或音效模型补充声音。

第一版不建议把音频延长作为核心验收要求，避免范围过大。

## 13. 画布节点规则

视频延长结果必须生成新节点，不覆盖原视频节点。

生成结果节点规则：

- 节点类型：视频结果节点。
- 默认标题：`视频延长`。
- 节点内容：完整延长后视频。
- 节点位置：原视频节点右侧或下游位置。
- 连线关系：原视频节点 -> 视频延长结果节点。
- 节点状态：处理中、成功、失败。

建议提交任务后立即创建一个下游「处理中」节点。任务完成后更新该节点，而不是等成功后才创建节点。

节点中建议保留：

- 原视频地址。
- 新增片段地址。
- 完整合成视频地址。
- 延长方向。
- 延长时长。
- 延长方式。
- 用户提示词。
- 自动分析提示词。
- 参考素材。
- 任务 ID。

## 14. 接口需求

正式版本建议由后端封装视频生成 API 和视频拼接逻辑，前端不直接调用模型供应商 API。

### 14.1 创建视频延长任务

```http
POST /api/video-extension/tasks
```

请求参数：

```json
{
  "projectId": "project_xxx",
  "sourceNodeId": "node_xxx",
  "sourceVideoUrl": "https://example.com/source.mp4",
  "direction": "tail",
  "duration": 8,
  "method": "motion-continuation",
  "prompt": "继续展示商品旋转，并推进到细节特写",
  "referenceAssets": [
    {
      "type": "image",
      "url": "https://example.com/reference.png"
    }
  ],
  "credits": 644
}
```

字段说明：

- `direction`：延长方向，`tail` 表示片尾延长，`head` 表示片头延长。
- `duration`：新增片段时长，单位秒。
- `method`：延长方式。
- `prompt`：用户提示词。
- `referenceAssets`：可选参考素材。
- `credits`：前端展示预计积分，最终以后端计算为准。

返回：

```json
{
  "taskId": "task_xxx",
  "status": "queued",
  "resultNodeId": "node_result_xxx"
}
```

### 14.2 查询视频延长任务

```http
GET /api/video-extension/tasks/:taskId
```

返回处理中：

```json
{
  "taskId": "task_xxx",
  "status": "processing",
  "progress": 42,
  "stage": "generating-extension-clip"
}
```

返回成功：

```json
{
  "taskId": "task_xxx",
  "status": "succeeded",
  "extensionClipUrl": "https://example.com/extension-clip.mp4",
  "videoUrl": "https://example.com/extended-video.mp4",
  "duration": 23,
  "extensionDuration": 8,
  "width": 1280,
  "height": 720,
  "fps": 30
}
```

返回失败：

```json
{
  "taskId": "task_xxx",
  "status": "failed",
  "errorCode": "VIDEO_EXTENSION_FAILED",
  "errorMessage": "视频延长失败，请调整提示词或缩短延长时长后重试"
}
```

## 16. 任务状态

视频延长任务需要支持以下状态：

| 状态 | 含义 |
| --- | --- |
| `idle` | 未开始 |
| `analyzing` | 正在分析原视频 |
| `extracting` | 正在提取首帧/尾帧和参考片段 |
| `submitting` | 正在提交生成任务 |
| `queued` | 任务排队中 |
| `generating` | 正在生成新增延长片段 |
| `stitching` | 正在拼接原视频和新增片段 |
| `succeeded` | 任务成功 |
| `failed` | 任务失败 |
| `canceled` | 任务取消 |

## 17. 异常处理

| 场景 | 提示文案 |
| --- | --- |
| 原视频不可用 | 当前视频不可用，无法延长 |
| 原视频无法提取首帧/尾帧 | 视频关键帧提取失败，请重新上传或更换视频 |
| 视频格式不支持 | 当前视频格式暂不支持延长 |
| 延长时长超过模型限制 | 延长时长超过当前模型支持上限 |
| 生成新增片段失败 | 视频延长片段生成失败，请调整提示词后重试 |
| 拼接失败 | 视频拼接失败，请稍后重试 |
| 积分不足 | 积分不足，无法提交视频延长 |
| API 超时 | 视频延长处理超时，请稍后查看任务结果 |

## 18. 限制规则

第一版建议增加明确限制：

- 单次延长时长不得超过模型最大输出时长。
- 支持视频格式：`MP4`、`MOV`、`WebM`。
- 最大原视频时长按业务和后端处理能力确定。
- 最大文件大小按后端和 API 限制确定。
- 片头延长效果不保证与原视频首帧完美无缝。
- 如果原视频动作复杂、镜头快速变化、主体快速出画，延长效果可能不稳定。
- 不保证新增片段能完美延续原视频音频。

## 19. 积分规则

建议规则：

- 积分主要按新增片段时长计算。
- 参考素材数量可以影响成本。
- 拼接和转码成本可计入基础费用。
- 任务创建成功后冻结积分。
- 任务成功后正式扣除积分。
- 任务失败或取消后释放冻结积分。
- 如果第三方 API 已经开始处理且无法取消，是否退积分由业务规则决定。

最终积分以后端计算为准，前端只负责展示预计值。

## 20. 验收标准

第一版验收需要满足：

1. 视频节点可以打开视频延长面板。
2. 用户可以选择片尾延长或片头延长。
3. 用户可以选择延长时长。
4. 用户可以选择延长方式。
5. 用户可以输入延长提示词。
6. 用户可以可选添加参考素材。
7. 点击生成后，会真实创建视频延长任务。
8. 后端会提取首帧/尾帧和参考片段。
9. 后端会调用视频生成 API 生成新增片段。
10. 后端会将新增片段与原视频拼接。
11. 任务成功后，画布中出现完整延长后视频节点。
12. 新节点播放的是完整延长后视频，不是原视频。
13. 原视频节点不会被覆盖。
14. 原视频节点和视频延长结果节点自动连接。
15. 任务失败时展示明确失败原因。
16. 参数、提示词、新增片段地址、完整视频地址和任务 ID 可以在节点数据中追溯。

## 21. 待确认问题

正式开发前必须确认以下问题：

1. 目标视频生成 API 最大输出时长是多少？
2. API 是否支持尾帧作为起始画面生成？
3. API 是否支持首帧作为结束画面生成？
4. API 是否支持参考视频输入？
5. API 是否支持返回生成片段尾帧？
6. API 是否支持指定分辨率、比例、帧率？
7. API 是否支持片头延长所需的反向衔接能力？
8. 后端拼接使用什么视频处理方案？
9. 拼接点是否需要默认过渡？
10. 原视频有音频时，新增片段音频如何处理？
11. 延长结果是否需要保留新增片段作为独立素材？
12. 如果片头延长效果不稳定，第一版是否默认只开放片尾延长？

## 22. 一句话总结

视频延长需要实现「基于原视频首帧/尾帧、参考片段、用户提示词和延长方式，生成新增延长片段，再由后端与原视频拼接成完整结果视频」。正式方案不要求视频生成模型直接输出完整长视频，模型只负责新增片段生成，后端负责拼接、转码和结果节点生成。
