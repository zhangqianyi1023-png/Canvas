# 图片节点需求文档

## 1. 需求背景

图片节点是画布创作流程中的核心节点之一。它既可以承载用户上传的图片，也可以承载 AI 生成图片、图片编辑结果、标注结果、裁剪结果、拆分结果等多种图片资产。

在画布工作流中，图片节点不仅是展示结果，还需要成为后续生成、编辑、素材沉淀和多模态引用的入口。

本需求文档面向正式项目开发，不包含具体接口字段和服务地址，只描述产品需求、交互要求和可能的技术实现方案。

## 2. 产品目标

图片节点需要支持以下目标：

- 展示单张图片和多张图片结果。
- 支持上传、替换、预览、下载、保存到素材库。
- 支持基础编辑：裁剪、旋转、调整像素、宫格拆分。
- 支持 AI 编辑：局部修改、擦除、扩图、增强、抠图、打光、角度控制。
- 支持批注标记。
- 支持节点标记和素材沉淀。
- 支持作为其他节点的输入，例如图生图、图生视频、角色图、3D 参考图等。
- 尽量保留原图，编辑类操作默认生成新节点，避免用户误覆盖。

## 3. 图片节点类型

### 3.1 上传图片节点

用户通过上传、拖拽、粘贴、素材库拖入等方式创建图片节点。

要求：

- 支持常见图片格式，例如 PNG、JPG、JPEG、WEBP。
- 上传完成后在画布中创建图片节点。
- 应记录图片尺寸、比例、来源、素材 ID 等基础信息。

### 3.2 AI 生成图片节点

图片生成任务完成后，以图片节点展示结果。

要求：

- 支持单张结果。
- 支持多张结果。
- 支持生成中状态。
- 支持任务查询或重试状态。
- 支持保存生成参数，方便后续追溯。

### 3.3 图片编辑结果节点

图片编辑工具生成的新图片，应作为新的图片节点落到画布。

适用工具：

- 裁剪
- 宫格拆分
- 标注
- 局部修改
- 擦除
- 扩图
- 增强
- 抠图
- 打光
- 角度控制
- 调整像素

建议规则：

- 默认创建新节点，不覆盖原图。
- 新节点与原节点自动连线。
- 新节点位置在原节点右侧或下游方向。
- 新节点标题体现操作来源，例如“裁剪结果”“局部修改结果”“扩图结果”。

### 3.4 多图结果节点

当一次生成返回多张图片时，节点需要支持多图管理。

要求：

- 默认展示封面图。
- 显示图片数量，例如“4 张”。
- 支持展开查看全部图片。
- 支持设置封面。
- 每张图片都应支持独立工具栏操作。
- 展开态下可对任意单图进行编辑、下载、保存、全屏查看。

## 4. 节点基础交互

### 4.1 选中

用户点击图片节点后，节点进入选中状态。

要求：

- 显示节点选中边框。
- 显示图片工具栏。
- 可拖拽移动节点。
- 可通过节点边界调整节点尺寸。

### 4.2 预览

用户双击图片，进入大图预览或全屏查看。

要求：

- 单图节点双击图片可打开大图预览。
- 多图节点收起态双击封面打开当前封面预览。
- 多图展开态双击某张图打开该图预览。
- 预览层支持关闭。
- 预览不应改变原图数据。

### 4.3 上传与替换

图片节点为空时，应提供上传入口。图片节点已有内容时，应支持替换图片。

要求：

- 空图片节点显示上传提示或上传按钮。
- 已有图片节点显示替换入口。
- 上传成功后更新节点图片。
- 替换操作需要保留节点位置、连接关系和基础配置。

### 4.4 拖拽与粘贴创建

用户可以通过拖拽文件或粘贴图片创建图片节点。

要求：

- 拖入画布的图片文件自动上传并创建节点。
- 粘贴图片时，如果没有选中图片节点，在画布中心创建新图片节点。
- 如果选中图片节点，可以作为替换当前图片的候选行为，具体是否覆盖需要产品确认。

## 5. 图片工具栏

### 5.1 工具栏展示时机

工具栏在以下场景展示：

- 图片节点被选中。
- 多图展开态中鼠标悬停某张图片。
- 空图片节点被选中时显示上传工具。

### 5.2 工具栏分组

建议分为以下几组：

1. 图片编辑工具：裁剪、角度控制、局部修改、打光、扩图、宫格拆分。
2. 更多工具：增强、调整像素、抠图、标注、擦除、合规认证、旋转。
3. 节点标记：添加标记。
4. 资产操作：上传或替换、添加到素材库、下载、全屏查看。
5. 任务操作：查询任务状态。

分组之间应使用竖线分隔。

### 5.3 工具栏按钮列表

| 工具 | 入口名称 | 说明 |
| --- | --- | --- |
| 上传/替换 | 上传文件 | 上传新图片或替换当前图片 |
| 裁剪 | 裁剪 | 裁剪图片并生成裁剪结果 |
| 角度控制 | 角度控制 | 通过 3D 相机视角生成新角度图片 |
| 局部修改 | 局部修改 | 涂抹局部区域并输入修改提示词 |
| 打光 | 打光 | 调整图片光源方向、亮度、色温 |
| 扩图 | 扩图 | 扩展画布范围并生成扩图结果 |
| 宫格拆分 | 宫格拆分 | 按网格拆分图片为多个图片节点 |
| 增强 | 增强 | 超分、细节增强或肤质优化 |
| 调整像素 | 调整像素 | 输入目标宽高并生成指定尺寸图片 |
| 抠图 | 抠图 | 选择主体后生成透明背景图 |
| 标注 | 标注 | 在图片上画批注并导出批注图 |
| 擦除 | 擦除 | 选择需要移除区域并生成擦除结果 |
| 合规认证 | Seedance2.0 合规认证 | 检查图片是否符合模型生成要求 |
| 旋转 | 旋转 | 旋转、镜像图片 |
| 添加标记 | 添加标记 | 给节点添加颜色标记 |
| 添加到素材库 | 添加到素材库 | 保存图片到素材库 |
| 下载 | 下载 | 下载当前图片 |
| 全屏查看 | 全屏查看 | 打开全屏预览 |

### 5.4 工具栏详细交互规格

图片节点工具栏不是普通按钮集合，而是一个“图片操作控制中心”。它需要同时处理普通操作、二级菜单、进入编辑模式、编辑中工具栏替换、生成参数面板和异步任务状态。

#### 5.4.1 工具栏默认布局

工具栏默认由左到右排列：

1. 主编辑区：裁剪、角度控制、局部修改、打光、扩图、宫格拆分。
2. 更多入口：收纳增强、调整像素、抠图、标注、擦除、合规认证、旋转。
3. 标记区：添加标记。
4. 资产区：上传/替换、添加到素材库、下载、全屏查看。
5. 任务区：查询任务。

布局要求：

- 每个按钮默认使用图标展示。
- hover 显示 tooltip。
- 当前激活工具需要有 active 状态。
- 不同分组之间用竖线分割。
- 工具栏应避开节点头部、画布边缘和浏览器边缘。
- 如果工具栏超出视口，应自动调整位置，不应被裁切。
- 工具栏点击不应触发画布拖拽、不应选中其他节点。

#### 5.4.2 工具栏展示状态

工具栏至少有以下状态：

| 状态 | 说明 |
| --- | --- |
| 默认隐藏 | 未选中、未悬停图片时隐藏 |
| 选中显示 | 节点被选中时显示 |
| 悬停显示 | 多图展开态中悬停某一张图片时显示 |
| 编辑中隐藏 | 进入某个工具编辑态后，普通工具栏隐藏 |
| 编辑工具栏显示 | 裁剪、局部修改、标注等工具进入编辑态后显示专用工具栏 |
| 任务中限制 | 图片生成中、上传中或保存中时，部分按钮禁用 |

#### 5.4.3 空图片节点工具栏

空图片节点不应展示完整编辑工具。

空态只展示：

- 上传文件。
- 删除节点，若节点系统有统一删除入口可不在图片工具栏重复出现。
- 可选：添加标记。

隐藏：

- 裁剪。
- 局部修改。
- 扩图。
- 下载。
- 全屏。
- 添加到素材库。
- 所有依赖图片内容的工具。

#### 5.4.4 单图节点工具栏

单图节点有图片内容后，应展示完整工具栏。

点击不同工具后的行为：

| 工具 | 点击后行为 |
| --- | --- |
| 裁剪 | 进入裁剪编辑态，普通工具栏隐藏，显示裁剪工具栏和裁剪框 |
| 角度控制 | 打开多角度编辑器浮层 |
| 局部修改 | 进入遮罩绘制态，显示遮罩工具栏和生成参数面板 |
| 打光 | 打开打光浮层 |
| 扩图 | 进入扩图面板，展示可拖拽扩图区域 |
| 宫格拆分 | 打开宫格预设菜单；选择预设后进入宫格编辑态 |
| 更多 | 打开更多工具菜单 |
| 添加标记 | 打开颜色标记菜单 |
| 上传/替换 | 打开文件选择器 |
| 添加到素材库 | 打开保存到素材库弹窗 |
| 下载 | 直接下载当前图片 |
| 全屏 | 打开全屏图片查看 |
| 查询 | 查询当前节点异步生成任务 |

#### 5.4.5 多图节点工具栏

多图节点分为收起态和展开态。

收起态：

- 工具栏操作对象是当前封面图。
- 工具栏中展示的下载、全屏、编辑工具默认作用于封面图。
- 用户点击“几张”按钮后展开全部图片。

展开态：

- 每张图片都有自己的工具栏。
- 工具栏操作对象是当前悬停的那一张图片。
- 每张图片可独立下载、全屏、保存到素材库、编辑。
- 每张图片可以设置为封面。
- 设置封面后，收起态展示该图片。

#### 5.4.6 更多工具菜单

更多工具菜单用于收纳低频工具，避免主工具栏过长。

建议菜单项：

- 增强
- 调整像素
- 抠图
- 标注
- 擦除
- Seedance2.0 合规认证
- 旋转

交互要求：

- 点击“更多”打开菜单。
- 再次点击“更多”关闭菜单。
- 点击菜单外关闭菜单。
- 按 Escape 关闭菜单。
- 点击菜单项后关闭菜单，并进入对应工具。
- 如果某工具不可用，应置灰并展示原因。

#### 5.4.7 宫格拆分二级菜单

宫格拆分是主工具栏中的复杂菜单工具。

一级入口：

- 点击“宫格拆分”打开拆分预设菜单。

预设菜单建议包含：

- 2 x 2
- 3 x 3
- 4 x 4
- 自定义

自定义菜单：

- hover 或点击“自定义”后打开右侧二级面板。
- 二级面板展示行列选择网格。
- 建议最大支持 5 x 5。
- 低于 2 x 2 的组合不可选择。
- 用户 hover 不同格子时，预览当前行列。
- 点击后进入宫格拆分编辑态。

进入宫格拆分编辑态后：

- 普通图片工具栏隐藏。
- 图片上覆盖宫格分割线。
- 用户可点击格子选择或取消选择。
- 用户可拖动分割线微调切分位置。
- 顶部或浮动工具栏展示：取消、已选数量、重置切分、确认拆分。
- 未选择任何格子时，确认拆分按钮禁用或点击后提示。

#### 5.4.8 添加标记菜单

添加标记是节点级能力，不是图片编辑能力。

交互要求：

- 点击添加标记打开颜色菜单。
- 颜色菜单显示可选颜色。
- 已选颜色显示 check 或高亮。
- 点击颜色可切换选中/取消。
- 选择后菜单可自动关闭，也可保持打开，取决于是否支持多选。
- 推荐支持多选颜色标记。
- 标记状态应体现在工具栏按钮上，例如显示颜色点。

#### 5.4.9 工具激活互斥规则

同一时间只能进入一个图片编辑工具。

互斥规则：

- 打开裁剪时，关闭局部修改、擦除、角度控制、打光、标注、宫格拆分、扩图等状态。
- 打开局部修改时，关闭其他编辑态。
- 打开打光时，关闭其他编辑态。
- 打开更多菜单不算编辑态，但点击菜单项后进入对应编辑态。
- 打开素材库保存弹窗时，图片工具栏可隐藏，避免遮挡弹窗。

原因：

- 避免多个浮层同时修改同一张图片。
- 避免用户不知道当前操作作用于哪个工具。
- 降低画布事件冲突。

#### 5.4.10 编辑态通用规则

进入任何图片编辑态后，需要遵守以下规则：

- 普通图片工具栏隐藏。
- 当前图片节点应增加编辑中视觉状态。
- 画布拖拽、节点拖拽、滚轮缩放等行为不应干扰编辑操作。
- 编辑工具栏和编辑面板需要使用 `nodrag`、`nopan` 或等效事件隔离。
- Escape 应优先关闭当前编辑态。
- 点击取消应恢复到普通图片节点，不改变图片。
- 生成或保存过程中，取消按钮、参数按钮需要根据风险禁用。
- 失败时保留编辑态和用户参数，方便重试。

#### 5.4.11 工具产物通用规则

工具分为三类产物：

1. 即时操作：下载、全屏、添加标记。
2. 本地图像处理：裁剪、旋转、调整像素、标注、宫格拆分。
3. 模型生成处理：局部修改、擦除、扩图、增强、抠图、打光、角度控制。

产物规则：

- 即时操作不创建新节点。
- 本地图像处理默认创建新节点；旋转可在产品上提供“替换原图”选项。
- 模型生成处理默认创建新节点。
- 所有新节点都应连接原节点。
- 新节点应保留来源操作类型和必要参数。
- 原图不应被删除。

#### 5.4.12 工具栏按钮禁用规则

以下情况按钮需要禁用：

| 场景 | 禁用内容 |
| --- | --- |
| 图片为空 | 除上传外的大部分工具 |
| 图片正在生成 | 所有编辑工具、下载、保存素材 |
| 图片上传中 | 替换、编辑、保存素材 |
| 当前工具生成中 | 当前工具参数、重复生成、取消按钮视情况禁用 |
| 模型不支持 | 对应 AI 编辑工具 |
| 无素材库权限 | 添加到素材库 |
| 跨域图片不可读 | 需要 canvas 像素读取的本地工具 |

#### 5.4.13 工具栏反馈规则

工具栏需要提供明确反馈：

- hover tooltip：说明按钮用途。
- active 状态：说明当前工具已打开。
- loading 状态：说明正在处理。
- error 状态：说明提交失败或参数不合法。
- disabled tooltip：说明为什么不可用。

#### 5.4.14 工具栏与画布层级

图片工具栏会和画布、节点、浮层、弹窗同时存在，层级需要明确。

推荐层级从低到高：

1. 画布背景。
2. 图片节点。
3. 图片节点内遮罩/编辑覆盖层。
4. 图片工具栏。
5. 图片工具二级菜单。
6. 图片编辑参数面板。
7. 全屏预览。
8. 全局弹窗，例如保存到素材库。

要求：

- 工具栏不应被节点裁切。
- 二级菜单不应被节点裁切。
- 全屏预览必须盖过画布。
- 保存到素材库弹窗必须盖过工具栏。

### 5.5 各工具在工具栏中的完整交互说明

#### 5.5.1 裁剪

入口：

- 主工具栏直接展示。

点击后：

- 关闭普通图片工具栏。
- 图片上出现裁剪框。
- 裁剪框默认覆盖图片主要区域。
- 出现裁剪专用工具栏。

裁剪专用工具栏包含：

- 取消。
- 宽高比。
- 重置。
- 保存。

宽高比菜单建议包含：

- 自由。
- 原图比例。
- 1:1。
- 3:4。
- 4:3。
- 9:16。
- 16:9。
- 其他项目常用比例。

编辑操作：

- 拖动裁剪框内部移动区域。
- 拖动 8 个控制点改变大小。
- 选择固定比例后，拖动控制点时保持比例。
- 重置恢复默认裁剪框。

确认：

- 点击保存后裁切图片。
- 生成新图片节点。
- 退出裁剪态。

取消：

- 点击取消或 Escape 退出。
- 不生成结果，不改变原图。

#### 5.5.2 角度控制

入口：

- 主工具栏直接展示。

点击后：

- 打开多角度编辑器浮层。
- 普通工具栏隐藏或保持弱显示，建议隐藏。

编辑器结构：

- 顶部：标题、关闭按钮。
- 快捷视角预设区。
- 左侧：3D 相机预览。
- 右侧：参数控制。
- 底部：生成参数和生成按钮。

快捷视角：

- 正面。
- 左侧。
- 右侧。
- 俯视。

#### 5.5.12 Seedance2.0 合规认证

入口：

- 在更多工具菜单中。

点击后：

- 打开 Seedance2.0 合规认证确认浮层，或直接进入提交认证流程。建议第一版使用确认浮层，避免用户误消耗认证次数。
- 用户确认后，将当前图片提交给 Seedance2.0/火山方舟相关认证能力。
- 节点进入“认证中”状态。
- 工具栏可显示 loading 或状态提示。
- 认证期间该按钮禁用，避免重复提交。

确认浮层建议包含：

- 标题：Seedance2.0 合规认证。
- 图片预览：展示将要提交认证的图片缩略图。
- 说明文案：用于确认该图片是否可作为 Seedance2.0 生成参考素材。
- 状态提醒：认证结果由 Seedance2.0 返回，系统不会用本地规则替代认证。
- 按钮：取消、开始认证。

结果：

- 通过。
- 不通过。
- 警告。

结果展示：

- 通过时显示“已通过 Seedance2.0 合规认证”。
- 不通过时显示“未通过 Seedance2.0 合规认证”。
- 警告时显示“需补充授权/需人工确认/图片存在风险”等状态。
- 应展示 Seedance2.0 返回的原因、风险项或建议。
- 建议提供“查看详情”入口。
- 如果认证结果带有效期，需要展示认证有效期。
- 如果认证结果返回认证 ID，需要保存并展示在详情中。

开发需要调研：

- Seedance2.0/火山方舟是否提供图片合规认证、肖像授权、人脸验证、版权认证等独立接口。
- 认证输入要求：图片 URL、Base64、文件上传、图片格式、图片大小、图片分辨率。
- 认证返回结构：状态、认证 ID、失败原因、风险类型、有效期、是否需要人工审核。
- 认证是否异步：同步返回结果，还是返回任务 ID 后轮询。
- 认证是否区分用途：图生视频参考图、人物肖像图、版权素材图、品牌素材图是否有不同认证流程。
- 认证结果如何在后续 Seedance2.0 生成任务中复用：是否需要传认证 ID、授权 ID 或素材 ID。
- 认证失败后是否支持重新提交。
- 认证是否计费、限流、需要特殊权限。
- 是否存在企业空间/团队空间级别的认证资产库。
- 是否需要用户显式确认图片版权或肖像授权。

注意：

- 本地尺寸、格式、清晰度检查只能作为提交前的前置校验。
- 前置校验不能替代 Seedance2.0 合规认证。
- 前置校验通过，不代表 Seedance2.0 认证通过。
- 最终认证状态必须以 Seedance2.0/火山方舟返回结果为准。

### 5.6 工具栏设计交付说明

这一节用于给设计师明确“页面应该长什么样”。设计稿不只需要画一个工具栏，还需要画出工具栏、二级菜单、编辑态、弹窗、结果状态之间的完整关系。

#### 5.6.1 图片节点默认结构

图片节点在画布中建议由以下区域组成：

- 节点外框：展示选中态、hover 态、错误态。
- 节点标题区：展示节点名称、节点类型、可选状态标识。
- 图片内容区：展示单张图片、多图封面或空态上传提示。
- 状态区：展示生成中、上传中、认证中、失败、已保存到素材库等轻状态。
- 工具栏：悬浮在节点上方或图片上方，不占用图片内容区。

设计需要覆盖以下状态：

| 状态 | 设计要求 |
| --- | --- |
| 空节点 | 图片区域中间显示上传入口，工具栏只显示上传 |
| 单图节点 | 图片完整展示，选中后显示完整工具栏 |
| 多图收起 | 展示封面图，并显示图片数量入口 |
| 多图展开 | 每张图片有独立操作入口，可设置封面 |
| 生成中 | 图片区域显示 loading 或占位图，编辑类按钮禁用 |
| 失败 | 图片区域或状态区显示失败原因和重试入口 |
| 认证中 | 显示 Seedance2.0 认证中，认证按钮 loading |
| 认证通过 | 显示已认证标识，可查看认证详情 |
| 认证失败 | 显示未通过标识，可查看原因和重新认证 |

#### 5.6.2 工具栏视觉结构

工具栏建议是横向悬浮条，从左到右分为五个区域：

1. 编辑工具区：裁剪、角度控制、局部修改、打光、扩图、宫格拆分。
2. 更多工具区：一个“更多”按钮，收纳增强、调整像素、抠图、标注、擦除、Seedance2.0 合规认证、旋转。
3. 标记区：添加标记。
4. 素材区：上传/替换、添加到素材库、下载、全屏查看。
5. 任务区：查询任务，仅在存在任务时出现。

视觉要求：

- 每个工具默认用图标按钮表达，hover 后显示 tooltip。
- 分组之间使用竖线分隔，不使用大面积背景块强行分组。
- 工具栏高度、按钮尺寸、圆角、hover 色需要和文本节点、视频节点工具栏保持统一。
- 按钮之间距离要紧凑，避免工具栏过长。
- 禁用状态要能看出不可点击，但不要完全消失，除非该工具在当前状态完全不适用。
- 当前激活的工具需要有 active 状态，例如局部修改、裁剪、标注进入编辑态时。

#### 5.6.3 更多菜单设计

点击“更多”后出现下拉菜单。

菜单元素：

- 菜单容器。
- 工具图标。
- 工具名称。
- 工具说明，可选，用于复杂工具。
- 禁用态原因，可选。
- 分组分割线，可选。

建议菜单顺序：

1. 增强
2. 调整像素
3. 抠图
4. 标注
5. 擦除
6. Seedance2.0 合规认证
7. 旋转

菜单交互：

- hover 菜单项时有背景色。
- 点击菜单项后关闭菜单。
- 点击菜单外关闭菜单。
- 菜单不能被画布边缘裁切。
- 如果工具不可用，菜单项禁用并展示原因，例如“当前图片加载失败，无法编辑”。

#### 5.6.4 编辑态通用布局

裁剪、局部修改、标注、擦除、扩图等工具进入编辑态后，不应继续展示普通工具栏。设计应切换为对应工具的专用编辑态。

编辑态通用结构：

- 图片编辑区域：展示原图和编辑辅助层，例如裁剪框、遮罩、批注层、扩图边界。
- 专用工具条：展示当前工具需要的画笔、橡皮、撤销、重做、取消、完成等按钮。
- 参数面板：需要调用模型的工具展示提示词、模型、尺寸、张数、生成按钮。
- 底部或右侧操作区：展示取消、重置、生成、保存。

通用按钮：

- 取消：退出编辑态，不生成结果。
- 重置：恢复当前工具默认状态。
- 撤销：撤销上一步编辑。
- 重做：恢复被撤销的编辑。
- 完成/保存：对本地编辑生效。
- 生成：提交 AI 任务并生成新节点。

#### 5.6.6 AI 工具参数面板规范

需要调用模型的工具，参数面板要保持统一，避免每个工具长得不一样。

通用参数：

- 图片 API：当系统有多个图片服务时展示。
- 模型：展示当前工具可用模型。
- 比例：输出比例。
- 尺寸：输出尺寸或清晰度。
- 张数：生成数量。
- 提示词：仅局部修改、角度控制、扩图等需要描述生成意图的工具展示。
- 生成按钮：主操作按钮。

设计要求：

- 参数面板标题要说明当前工具，例如“局部修改参数”“扩图参数”。
- 模型下拉需要展示模型名称、供应商、能力标签。
- 不支持的参数不要展示，避免用户误以为可用。
- 参数变化不应立即提交任务，必须点击生成。
- 生成中按钮进入 loading，避免重复提交。

#### 5.6.7 结果生成后的画布表现

所有会产生新图片的工具，生成结果后都需要在画布中有一致表现。

要求：

- 新图片节点自动出现在原节点右侧或下游方向。
- 原节点与新节点自动连线。
- 新节点标题体现来源，例如“裁剪结果”“扩图结果”“打光结果”。
- 新节点保留来源信息，方便用户追溯。
- 原图不被覆盖，除非用户明确选择“替换原图”。
- 多结果时生成多图节点，或生成多个独立图片节点，需要产品在具体工具中确认。

#### 5.6.8 错误与空状态设计

设计稿需要覆盖这些常见异常：

- 图片加载失败。
- 图片跨域导致无法编辑。
- 图片格式不支持。
- 图片太大或太小。
- 上传失败。
- 模型不可用。
- 生成任务失败。
- 认证失败。
- 认证需要人工审核。
- 保存素材失败。
- 下载失败。

错误信息需要让普通用户看得懂，例如：

- 不建议只显示“Error 500”。
- 应显示“图片上传失败，请重新选择图片”。
- 技术错误码可以放在详情中，不要作为主文案。

### 5.7 开发调研清单

这一节用于给开发明确“需要调研哪些能力”。它不是接口设计，但需要帮助开发知道从哪里开始拆。

#### 5.7.1 图片文件与存储

需要调研：

- 当前项目图片文件上传走哪个服务。
- 上传后返回的是公网 URL、内网 URL、对象存储 URL，还是临时 URL。
- 图片编辑和模型 API 是否要求图片可公网访问。
- 是否需要把跨域图片转存到自己的文件服务。
- 是否需要生成缩略图。
- 是否需要记录原图、编辑结果图、预览图三种资源。
- 图片文件大小、格式、分辨率上限。

#### 5.7.2 前端本地图片处理

以下工具可以部分或全部在前端完成：

- 裁剪。
- 旋转。
- 镜像。
- 调整像素的基础 resize。
- 标注合成。
- 宫格拆分。

需要调研：

- 使用 Canvas、OffscreenCanvas、WebGL 还是现有图片处理库。
- 大图处理是否会卡顿或内存溢出。
- 跨域图片是否能被 canvas 安全绘制。
- 导出格式使用 PNG、JPEG 还是 WEBP。
- 是否需要保留 EXIF 方向信息。

#### 5.7.3 AI 图片编辑能力

以下工具需要模型或后端能力：

- 局部修改。
- 擦除。
- 扩图。
- 增强。
- 抠图。
- 打光。
- 角度控制。

需要调研：

- 哪些模型支持原图 + mask。
- 哪些模型支持 outpaint。
- 哪些模型支持主体分割或透明背景。
- 哪些模型支持图片超分。
- 哪些模型支持人像肤质优化。
- 哪些模型支持相机角度或视角控制。
- 哪些模型支持光照控制；如果不支持，是否只能把光照信息转成提示词。
- 每个模型支持的输入尺寸、输出尺寸、张数、耗时和价格。

#### 5.7.4 Mask 与涂抹编辑

局部修改、擦除、抠图都依赖用户在图片上选择区域。

需要调研：

- 前端如何保存用户绘制的 mask。
- mask 是黑白图、透明 PNG，还是矢量路径。
- mask 尺寸是否必须和原图一致。
- 用户缩放节点后，mask 坐标如何映射回原图像素坐标。
- 撤销/重做保存的是路径历史还是位图快照。
- 画笔边缘是否需要羽化。
- 移动端或触控板是否需要特殊适配。

#### 5.7.5 3D 控件能力

角度控制和打光都涉及 3D 可视化控件。

需要调研：

- 是否使用 Three.js。
- 是否已有可复用的 3D 控件。
- 透视/正面切换如何做动画。
- 光源点拖拽如何只响应灯光本身，不响应空白区域。
- 主光源和轮廓光如何在同一个控件里切换选中。
- 打光控件是否只是参数预览，还是需要真实影响图片预览。
- 3D 控件输出的是结构化参数，还是生成提示词。

#### 5.7.6 任务系统

AI 生成、增强、扩图、打光、认证等都可能是异步任务。

需要调研：

- 当前项目是否已有统一任务表或任务接口。
- 任务状态包括哪些：排队中、处理中、成功、失败、取消、审核中。
- 前端如何轮询任务。
- 用户刷新页面后任务状态如何恢复。
- 任务失败原因是否结构化。
- 是否支持取消任务。
- 是否支持任务完成后自动创建节点。

#### 5.7.7 素材库

添加到素材库需要和素材系统打通。

需要调研：

- 素材库是否区分个人空间和团队空间。
- 素材是否有文件夹。
- 是否支持图片标签。
- 素材库保存的是图片 URL，还是复制一份文件。
- 从画布保存到素材库后，是否需要保留来源节点 ID。
- 保存失败如何重试。

#### 5.7.8 Seedance2.0 合规认证

这部分必须以 Seedance2.0/火山方舟官方能力为准，不能用本地规则替代。

需要调研：

- 是否存在独立的图片合规认证 API。
- 认证能力的准确名称是什么。
- 认证图片的提交方式是什么：公网 URL、对象存储文件、Base64、文件流。
- 认证是否异步。
- 认证是否返回认证 ID、素材 ID、授权 ID 或审核任务 ID。
- 认证通过后，后续调用 Seedance2.0 图生视频是否必须携带认证结果。
- 真人肖像、版权素材、品牌素材是否有不同认证要求。
- 认证失败是否返回可展示给用户的原因。
- 是否有有效期。
- 是否支持重新认证。
- 是否计费、限流、需要开通权限。

产品和设计需要注意：

- “合规认证”不是简单的前端检查。
- 前端可以在提交前检查格式、大小、可访问性，但最终状态必须来自 Seedance2.0/火山方舟。
- 如果官方能力不支持完全 API 化，需要在需求中调整为“跳转控制台认证”或“人工认证后录入结果”。

#### 5.7.9 权限与安全

需要调研：

- 哪些用户可以上传图片。
- 哪些用户可以调用 AI 编辑。
- 哪些用户可以保存到团队素材库。
- 图片是否涉及敏感内容审核。
- 图片 URL 是否需要鉴权。
- 下载是否受权限控制。
- 团队空间里其他成员能否看到认证结果。

#### 5.7.10 埋点与可观测性

建议开发预留埋点：

- 工具栏展示次数。
- 每个工具点击次数。
- 编辑态取消率。
- 生成提交次数。
- 生成成功率。
- 生成失败原因。
- Seedance2.0 认证提交次数。
- 认证通过率、失败率、审核中比例。
- 添加到素材库成功率。
- 下载成功率。

## 6. 工具详细需求

## 6.1 上传 / 替换图片

### 功能目标

让用户快速把本地图片加入画布，或替换现有图片节点内容。

### 交互说明

- 空图片节点选中后，工具栏显示上传按钮。
- 已有图片节点内显示替换入口。
- 点击后打开系统文件选择器。
- 上传过程中显示上传中状态。
- 上传成功后更新节点图片。
- 上传失败时提示错误，不清空原图。

### 技术实现方案

- 前端读取本地文件并上传到后端文件服务。
- 后端返回可访问的图片 URL 和基础尺寸信息。
- 前端根据图片宽高设置节点默认比例。
- 图片 URL、尺寸、来源写入节点数据。

## 6.2 下载图片

### 功能目标

用户可以下载图片节点中的当前图片。

### 交互说明

- 点击下载按钮后开始下载。
- 下载文件名建议包含节点 ID 或图片标题。
- 跨域图片应通过后端代理或文件服务处理，避免浏览器 CORS 导致下载失败。
- 下载失败时显示错误提示。

### 技术实现方案

- 同源图片可直接前端 fetch 为 Blob 下载。
- 跨域图片可由后端代理下载后返回 Blob。
- data URL 图片可直接转换为 Blob。

## 6.3 全屏查看

### 功能目标

用户可以在不改变节点的情况下查看图片细节。

### 交互说明

- 点击全屏查看按钮打开全屏浮层。
- 全屏浮层居中展示图片。
- 点击关闭按钮或按 Escape 关闭。
- 点击遮罩区域也可关闭，点击图片本身不关闭。

### 技术实现方案

- 使用前端 Portal 将预览层挂载到 body。
- 预览层不改变节点状态，仅展示当前图片 URL。

## 6.4 添加到素材库

### 功能目标

用户可以将图片保存到素材库，供后续复用。

### 交互说明

- 点击“添加到素材库”打开保存弹窗。
- 可选择个人/团队空间。
- 可选择文件夹。
- 可新建文件夹。
- 保存成功后素材库新增图片素材。

### 保存内容

建议保存：

```json
{
  "type": "image",
  "name": "素材名称",
  "imageUrl": "图片地址",
  "source": "canvas",
  "sourceId": "来源节点 ID",
  "groupId": "素材库文件夹 ID",
  "createdAt": "创建时间",
  "updatedAt": "更新时间"
}
```

### 技术实现方案

- 复用素材库保存弹窗。
- 保存时只写入素材库数据，不复制图片文件。
- 如果图片是临时 URL，应先转存为正式素材 URL。

## 6.5 添加标记

### 功能目标

用户可以给图片节点添加颜色标记，用于分类或状态管理。

### 交互说明

- 点击添加标记按钮打开颜色菜单。
- 可选择或取消颜色。
- 已有标记时按钮需要体现选中状态。
- 标记是节点属性，不是图片内容的一部分。

### 技术实现方案

- 节点数据保存 `tagColors` 数组。
- 工具栏读取节点标记状态并展示颜色点。

## 6.6 裁剪

### 功能目标

用户可以裁剪图片并生成新的裁剪结果节点。

### 交互说明

- 点击裁剪进入裁剪模式。
- 图片上显示裁剪框。
- 支持拖动裁剪框移动。
- 支持拖动 8 个控制点调整尺寸。
- 支持选择宽高比。
- 支持重置裁剪框。
- 支持取消。
- 点击保存后生成新的裁剪结果节点。

### 结果规则

- 不覆盖原图。
- 生成新的图片节点。
- 新节点与原节点自动连线。
- 新节点根据裁剪后比例调整节点尺寸。

### 技术实现方案

- 前端 canvas 加载原图并根据裁剪框导出 Blob。
- 上传裁剪后的图片，返回新图片 URL。
- 创建新的图片节点。

## 6.7 旋转与镜像

### 功能目标

用户可以旋转或镜像当前图片。

### 交互说明

- 点击旋转按钮后进入旋转编辑模式。
- 支持自由角度旋转。
- 支持水平翻转。
- 支持垂直翻转。
- 支持取消。
- 保存后更新图片。

### 结果规则

旋转属于轻量修正类操作，可采用以下两种方案：

1. 覆盖当前图片：适合误拍方向修正。
2. 生成新节点：适合创作型旋转。

正式产品建议默认“生成新节点”，并提供“替换原图”选项，避免误覆盖。

### 技术实现方案

- 前端 canvas 按角度和翻转参数重新绘制图片。
- 导出 Blob 后上传。
- 根据产品规则更新当前节点或创建新节点。

## 6.8 宫格拆分

### 功能目标

用户可以将一张图片按网格切分成多个图片节点。

### 交互说明

- 点击宫格拆分打开预设菜单。
- 支持 2x2、3x3、4x4 等预设。
- 支持自定义行列，建议最多 5x5。
- 进入拆分模式后图片上显示网格。
- 用户可点击选择需要拆出的格子。
- 用户可拖动分割线微调切分位置。
- 支持重置切分。
- 支持取消。
- 点击确认后，为每个选中格子生成一个新图片节点。

### 结果规则

- 每个选中格子生成一个独立图片节点。
- 新节点保持与原图自动连线。
- 新节点按宫格位置自动排布。
- 不覆盖原图。

### 技术实现方案

- 前端根据网格比例计算每个格子的 crop 区域。
- 使用 canvas 裁切每个选中区域。
- 上传每个切片图片。
- 批量创建图片节点。

## 6.9 局部修改

### 功能目标

用户可以在图片上涂抹局部区域，并通过提示词生成局部修改结果。

### 交互说明

- 点击局部修改进入遮罩绘制模式。
- 工具栏提供画笔、橡皮、画笔大小、撤销、重做、清空。
- 用户在图片上涂抹需要修改的区域。
- 用户输入修改提示词。
- 可选择图片 API、模型、比例、尺寸、生成张数。
- 点击生成后创建新的局部修改结果节点。

### 校验规则

- 必须有遮罩。
- 必须有提示词。
- 必须选择可用模型。

### 结果规则

- 不覆盖原图。
- 创建新图片节点。
- 新节点连接原图片节点。
- 新节点保存来源图、遮罩和提示词信息，方便追溯。

### 技术实现方案

- 前端将用户绘制区域转换为 mask 图片。
- 将原图、mask、提示词、生成参数提交给支持 inpaint 的模型能力。
- 生成结果作为新图片节点返回。

## 6.10 擦除

### 功能目标

用户可以涂抹需要移除的区域，让模型自动补全背景。

### 交互说明

- 点击擦除进入遮罩绘制模式。
- 支持画笔、矩形、橡皮、画笔大小、撤销、重做、清空。
- 用户标记需要擦除的区域。
- 点击生成后创建擦除结果节点。

### 校验规则

- 必须存在遮罩。
- 无需用户输入提示词，可使用内置提示词，例如“擦除选中区域”。

### 技术实现方案

- 与局部修改类似，核心也是原图 + mask。
- 提示词可由系统内置。
- 后端选择支持 erase/inpaint 的模型执行。

## 6.11 扩图

### 功能目标

用户可以扩展图片画布，让模型补全原图外的内容。

### 交互说明

- 点击扩图后，图片周围出现可拖拽扩展区域。
- 用户可拖动上、下、左、右、四角控制点调整扩图范围。
- 支持选择目标宽高比。
- 支持自由扩图。
- 支持选择分辨率、质量、数量、模型。
- 点击生成后创建扩图结果节点。

### 结果规则

- 不覆盖原图。
- 新节点尺寸根据扩图后的目标比例自动调整。
- 保留原图在扩图画布中的位置关系。

### 技术实现方案

- 前端记录原图在扩展画布中的相对位置。
- 根据扩展区域生成 outpaint 参数。
- 后端或模型根据原图和扩展范围生成补全图片。

## 6.12 角度控制

### 功能目标

用户可以通过类似 3D 相机控制的方式生成图片的新角度。

### 交互说明

- 点击角度控制打开多角度编辑器。
- 左侧展示 3D 相机预览。
- 支持快捷视角预设。
- 支持水平环绕角度调整。
- 支持垂直俯仰角度调整。
- 支持相机距离调整。
- 支持输入补充提示词。
- 支持选择图片 API、模型、比例、尺寸、张数。
- 点击生成后创建新角度图片节点。

### 技术实现方案

- 前端用 Three.js 或等效 3D 预览控件模拟相机视角。
- 将视角参数转换为自然语言提示词或结构化控制参数。
- 使用图生图模型基于原图生成新角度。
- 如果模型支持明确相机控制，应优先使用结构化参数。
- 如果模型不支持，则将角度参数写入提示词中。

## 6.13 打光

### 功能目标

用户可以调整图片主体的光照方向、亮度、色温和轮廓光，并生成新的打光结果。

### 交互说明

- 点击打光打开灯光控制浮层。
- 左侧展示 3D 灯光控制器。
- 支持透视/正面视角切换。
- 支持主光源位置选择：左侧、顶部、右侧、前方、底部、后方。
- 支持拖动灯光点调整光源位置。
- 打开轮廓光后显示第二个灯光。
- 只有拖动灯光点本身才移动灯光，拖动空白区域不应误移动灯光。
- 支持亮度调节。
- 支持色温调节。
- 亮度和色温需要影响可视化锥形光效果。
- 点击生成后创建打光结果节点。

### 技术实现方案

- 前端使用 Three.js 渲染光照控制器。
- 主光源和轮廓光可用 SpotLight 可视化。
- 光锥颜色由色温映射。
- 光锥透明度或强度由亮度映射。
- 正式生成可走图生图模型，输入原图、光照方向、亮度、色温、轮廓光等参数。

## 6.14 增强

### 功能目标

用户可以提升图片清晰度、细节或人像肤质。

### 交互说明

- 点击增强打开增强面板。
- 支持模式切换：
  - 超分放大
  - 肤质优化
- 超分放大支持选择模型、放大风格、放大倍数。
- 肤质优化支持选择模式，例如自然、标准、强力。
- 点击生成后创建增强结果节点。

### 技术实现方案

- 超分可使用超分辨率模型。
- 细节增强可使用图像增强模型或图生图模型。
- 肤质优化可使用人像增强模型。
- 若一个模型不支持全部能力，前端需要根据模型能力展示可用选项。

## 6.15 调整像素

### 功能目标

用户可以指定输出图片的像素宽高。

### 交互说明

- 点击调整像素打开面板。
- 输入宽度 px。
- 输入高度 px。
- 输入值必须为合法整数。
- 点击生成后创建指定尺寸结果节点。

### 校验规则

- 宽高必须大于 0。
- 宽高不能超过系统限制。
- 输入非法时显示错误，不提交。

### 技术实现方案

- 基础方案：前端 canvas resize。
- 高质量方案：后端使用图像处理库或模型进行重采样。
- 如果涉及超分，应归入增强工具，而不是普通调整像素。

## 6.16 抠图

### 功能目标

用户可以保留主体并移除背景，生成透明背景图片。

### 交互说明

- 点击抠图打开抠图面板。
- 用户涂抹需要保留的主体区域。
- 支持画笔、橡皮、撤销、重做。
- 点击生成后创建抠图结果节点。
- 结果应支持透明背景预览。

### 技术实现方案

- 可使用主体分割模型或图像 matting 模型。
- 如果用户提供了保留区域，可作为分割提示。
- 输出建议为 PNG，保留 alpha 通道。

## 6.17 标注

### 功能目标

用户可以在图片上添加说明、箭头、框选和文字，生成批注图。

### 交互说明

- 点击标注进入批注模式。
- 支持工具：
  - 画笔
  - 箭头
  - 矩形
  - 圆形
  - 文字
  - 橡皮
- 支持选择颜色。
- 支持调整线宽。
- 支持撤销、重做。
- 点击完成后导出批注图并生成新节点。

### 结果规则

- 不覆盖原图。
- 生成新的批注结果节点。
- 批注内容烘焙到新图片中。

### 技术实现方案

- 前端 canvas 叠加绘制批注层。
- 完成时将原图和批注层合成为一张 PNG。
- 上传合成图后创建新节点。

## 6.18 Seedance2.0 合规认证

### 功能目标

将图片提交给 Seedance2.0/火山方舟相关合规认证能力，确认该图片是否可以作为 Seedance2.0 视频生成的参考素材。

这里的“合规认证”不是前端本地判断，也不是简单检查图片尺寸，而是对接 Seedance2.0 官方或供应商提供的认证能力，由对方返回认证结果。

典型认证目标包括：

- 图片是否可作为 Seedance2.0 图生视频参考图。
- 图片是否涉及真人肖像授权。
- 图片是否涉及版权风险。
- 图片是否存在内容安全风险。
- 图片是否需要额外授权或人工审核。

### 交互说明

- 用户点击“Seedance2.0 合规认证”。
- 系统弹出确认浮层，说明即将把当前图片提交给 Seedance2.0 认证能力。
- 用户点击“开始认证”。
- 节点显示“认证中”状态。
- 认证按钮进入 loading 或禁用状态。
- 认证完成后，节点显示认证结果。
- 如果认证失败，应展示 Seedance2.0 返回的失败原因和建议。
- 如果认证需要人工审核，应展示“审核中”状态。
- 如果认证通过，应保存认证结果，后续调用 Seedance2.0 生成时可复用。

### 页面元素

认证确认浮层建议包含：

- 图片缩略图。
- 标题：Seedance2.0 合规认证。
- 说明：将当前图片提交给 Seedance2.0 进行合规认证。
- 风险提示：请确认图片版权、肖像授权和使用权归属。
- 按钮：取消、开始认证。

认证中状态建议包含：

- 节点状态条：Seedance2.0 认证中。
- 工具栏按钮 loading。
- 不允许重复提交认证。

认证结果状态建议包含：

- 已通过：绿色状态。
- 未通过：红色状态。
- 需审核：黄色状态。
- 认证过期：灰色或黄色状态。
- 查看详情入口。

认证详情建议展示：

- 认证状态。
- 认证 ID。
- 提交时间。
- 完成时间。
- 有效期。
- 风险项。
- 失败原因。
- 官方建议。

### 技术实现方案

- 前端负责触发认证、展示状态和结果。
- 后端负责调用 Seedance2.0/火山方舟认证能力。
- 认证请求应使用正式可访问的图片 URL，或按 Seedance2.0 要求上传图片文件/Base64。
- 如果认证是异步任务，后端需要保存任务 ID，前端轮询或通过任务状态接口查询。
- 认证结果需要写回图片节点数据。
- 后续调用 Seedance2.0 生成任务时，应携带认证结果要求的认证 ID、授权 ID 或素材 ID。

开发需要重点调研：

- Seedance2.0 是否有独立的图片认证接口。
- 肖像授权、人脸验证、版权认证是否是同一个流程。
- 认证是否必须在火山方舟控制台先完成，还是可以完全 API 化。
- 认证结果能否跨任务复用。
- 认证结果是否绑定图片 URL、图片 hash、用户、空间或项目。
- 认证失败原因是否结构化。
- 是否支持批量认证。
- 是否有回调机制。
- 认证是否需要用户签署授权确认。
- API 是否要求图片存储在指定对象存储或可公网访问。

前置校验可以做，但只能作为提交前提醒：

- 图片格式是否支持。
- 图片大小是否超过限制。
- 图片是否可公网访问。
- 图片是否过小或过大。
- 图片是否读取失败。

前置校验不等于合规认证。最终结果必须以 Seedance2.0 返回为准。
- 结果写入节点状态。

图片节点建议结构：

```json
{
  "id": "node_xxx",
  "type": "result",
  "data": {
    "resultType": "generateImage",
    "label": "图片",
    "imageUrl": "当前封面图片地址",
    "imageUrls": ["图片地址 1", "图片地址 2"],
    "coverIndex": 0,

    "imageSize": "3:4",

      "width": 1024,

    },

      "图片地址": {

      }
    },

    "tagColors": [],
    "generationConfig": {},
    "operation": "",
    "prototypeSettings": {},
    "taskIds": [],

  },
  "position": {
    "x": 100,
    "y": 100
  },
  "style": {

  }

```

字段说明：

| 字段 | 说明 |
| --- | --- |

## 9. 产物规则

### 9.1 默认生成新节点

除非用户明确选择“替换原图”，所有编辑类工具默认生成新节点。

原因：

- 保留原图更安全。
- 用户可以对比不同版本。
- 更符合画布工作流的分支式创作方式。

### 9.2 自动连线

新节点应自动连接来源节点。

要求：

- 原节点作为 source。
- 新节点作为 target。
- 连接关系用于表达编辑来源。

### 9.3 自动布局

新节点应出现在来源节点右侧或下游方向。

要求：

- 避免覆盖原节点。
- 批量生成时自动错位排列。
- 宫格拆分结果应按网格顺序排列。

## 10. 技术实现建议

### 10.1 前端图像处理

适合前端处理的功能：

- 裁剪
- 旋转
- 镜像
- 调整像素基础版
- 标注合成
- 宫格拆分
- 遮罩绘制

原因：

- 这些能力可通过 canvas 实现。
- 处理速度快。
- 不一定需要模型。

### 10.2 模型图像处理

适合模型处理的功能：

- 局部修改
- 擦除
- 扩图
- 抠图
- 增强
- 打光
- 角度控制

原因：

- 这些能力需要语义理解、内容补全或风格生成。
- 传统图像算法难以达到自然效果。

### 10.3 能力适配

不同模型支持能力不同，前端不应硬编码所有模型都支持所有工具。

建议按能力展示：

```json
{
  "inpaint": true,
  "outpaint": true,
  "imageToImage": true,
  "upscale": true,
  "cutout": true
}
```

如果模型不支持某工具：

- 工具按钮可隐藏或禁用。
- 禁用时提示需要切换模型。

### 10.4 遮罩规范

局部修改、擦除、抠图都可能用到遮罩。

建议统一遮罩规范：

- 白色表示保留或操作区域，需要按具体工具定义清楚。
- 黑色表示非操作区域。
- 遮罩尺寸应与原图一致。
- 前端显示遮罩时可以用半透明颜色，提交时转换为模型需要的黑白 mask。

### 10.5 跨域图片处理

图片下载、canvas 编辑、标注合成等能力需要读取图片像素。

需要注意：

- 跨域图片如果没有 CORS，前端 canvas 会被污染。
- 应通过后端代理或统一文件服务把图片转为同源可访问地址。
- 上传和生成结果建议统一落到同一文件服务。

## 11. 错误和边界

### 11.1 图片为空

空图片节点只展示上传入口，不展示编辑工具。

### 11.2 图片正在生成

生成中图片不可编辑。

允许：

- 查看任务状态。
- 查询任务。
- 取消任务（如果系统支持）。

不允许：

- 裁剪。
- 下载不存在的图片。
- 保存到素材库。

### 11.3 工具提交校验

不同工具提交前需要校验：

| 工具 | 必填条件 |
| --- | --- |
| 裁剪 | 有图片，有合法裁剪框 |
| 宫格拆分 | 至少选择一个格子 |
| 局部修改 | 有遮罩，有提示词，有模型 |
| 擦除 | 有遮罩，有模型 |
| 扩图 | 有图片，有扩图区域，有模型 |
| 抠图 | 有图片，有主体区域或自动主体检测 |
| 增强 | 有图片，有增强模式 |
| 调整像素 | 宽高合法 |
| 标注 | 有批注内容 |
| 角度控制 | 有图片，有模型 |
| 打光 | 有图片，有灯光参数 |

### 11.4 失败处理

工具执行失败时：

- 保留原图。
- 不创建空结果节点，或创建失败状态节点供重试。
- 显示明确错误原因。
- 用户可以修改参数后重试。

- 多张图片默认展示封面。

- 可设置封面。
- 每张图片可独立打开工具栏。

### 13.3 编辑工具

- 裁剪可生成裁剪结果节点。
- 旋转/镜像可生成或保存结果。
- 宫格拆分可生成多个切片节点。

- 编辑类操作默认不覆盖原图。
- 操作失败不影响原图。
- 工具面板打开时不误触发画布拖拽。
- Escape 可以退出可取消的编辑状态。
