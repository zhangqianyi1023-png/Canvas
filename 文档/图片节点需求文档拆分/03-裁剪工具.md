# 图片节点裁剪工具需求文档

## 1. 文档说明

本文描述图片节点工具栏中的“裁剪”工具。

裁剪工具的核心目标是：用户在不破坏原图的前提下，选择图片中的一块区域，把这块区域导出成一张新的图片，并在画布中生成一个新的图片节点。

一句话理解：

用户点击图片节点上的“裁剪”，图片上出现一个可拖动、可缩放的裁剪框；用户调整好范围后点击保存，系统生成一个“裁剪结果”图片节点。

## 2. 功能定位

### 2.1 这个工具解决什么问题

用户在画布中经常会遇到这些需求：

- 只想保留图片中的一个主体。
- 想把横图裁成竖图。
- 想把一张大图裁成适合封面、海报、视频首帧的比例。
- 想从生成图里截出局部细节继续加工。
- 想去掉图片边缘多余空白。
- 想把图片裁成社媒平台需要的比例。

裁剪工具就是给用户一个最基础、最可靠的图片局部提取能力。

### 2.2 它和其他工具的区别

| 工具 | 是否改变图片内容 | 是否调用 AI | 输出 |
| --- | --- | --- | --- |
| 裁剪 | 不改变内容，只改变可见区域 | 不需要 | 新图片节点 |
| 扩图 | 会让模型补出图片外的内容 | 需要 | 新图片节点 |
| 局部修改 | 会修改被涂抹区域内容 | 需要 | 新图片节点 |
| 擦除 | 会移除选中区域并补背景 | 需要 | 新图片节点 |
| 调整像素 | 改变图片尺寸，通常不改变构图 | 不一定需要 | 新图片节点 |
| 旋转 | 改变方向或角度 | 不需要 | 新图片节点或替换 |

裁剪是一个本地图片处理工具，不应该默认消耗 AI 额度。

## 3. 用户目标

用户可以：

- 进入裁剪模式。
- 移动裁剪框。
- 缩放裁剪框。
- 选择固定宽高比。
- 使用自由比例裁剪。
- 重置裁剪范围。
- 取消裁剪。
- 保存裁剪结果。
- 得到一个新的图片节点。
- 保留原图不变。

## 4. 设计目标

设计师需要明确：

- 裁剪按钮在图片工具栏中的位置。
- 进入裁剪态后普通工具栏如何变化。
- 裁剪专用工具栏有哪些按钮。
- 裁剪框长什么样。
- 裁剪框外的遮罩怎么表现。
- 8 个拖拽点如何显示。
- 宽高比菜单如何展示。
- 保存中、失败、禁用状态如何展示。

## 5. 开发目标

开发需要明确：

- 裁剪框坐标如何保存。
- 鼠标拖动如何换算成图片坐标。
- 固定比例如何约束裁剪框。
- 裁剪结果如何用 canvas 导出。
- 图片跨域时如何处理。
- 裁剪结果如何上传。
- 如何创建新的图片节点。
- 如何记录来源关系。

## 6. 功能入口

### 6.1 入口位置

入口位于图片节点选中后的图片工具栏中。

按钮名称：

```text
裁剪
```

按钮建议：

- 使用裁剪图标。
- hover 显示 tooltip：裁剪。
- 不使用长文字按钮，避免工具栏过宽。

### 6.2 展示条件

以下情况显示裁剪按钮：

- 图片节点有可用图片。
- 图片节点被选中。
- 多图展开态中，用户悬停某一张图片。

以下情况不应显示或应禁用：

- 图片节点为空。
- 图片正在上传。
- 图片正在生成。
- 图片加载失败。
- 图片地址不可访问。
- 当前节点不支持图片编辑。

### 6.3 点击入口后的行为

用户点击“裁剪”后：

- 普通图片工具栏隐藏。
- 图片进入裁剪编辑态。
- 图片上出现裁剪框。
- 图片上出现裁剪辅助遮罩。
- 顶部或附近出现裁剪专用工具栏。

## 7. 裁剪编辑态整体布局

### 7.1 页面结构

裁剪编辑态包含：

- 图片显示区域。
- 裁剪框。
- 裁剪框外遮罩。
- 九宫格辅助线。
- 8 个拖拽控制点。
- 裁剪专用工具栏。
- 错误提示区。

### 7.2 裁剪专用工具栏

工具栏建议包含三组：

第一组：

- 取消。

第二组：

- 宽高比。
- 重置。

第三组：

- 保存。

保存失败时：

- 工具栏中展示错误提示。

保存中时：

- 保存按钮显示“保存中”。
- 保存按钮图标变成 loading。
- 取消、宽高比、重置、拖拽点禁用。

### 7.3 工具栏位置

工具栏建议浮动在图片节点上方。

要求：

- 不遮挡裁剪框关键区域。
- 不被浏览器视口裁切。
- 跟随节点位置移动。
- 在画布缩放时仍然保持屏幕可读大小。

## 8. 裁剪框初始状态

### 8.1 默认裁剪框

进入裁剪模式后，裁剪框默认覆盖图片主体区域。

建议默认值：

- 距离图片左侧约 12%。
- 距离图片顶部约 12%。
- 宽度约 76%。
- 高度约 76%。

这样可以避免一进入裁剪就全图选中，用户更容易理解当前处于“选择区域”的状态。

### 8.2 初始裁剪框限制

裁剪框必须满足：

- 在图片范围内。
- 宽度大于最小值。
- 高度大于最小值。
- 不超出图片边界。

### 8.3 多图场景

如果图片节点有多张图片：

- 在收起态裁剪封面图。
- 在展开态裁剪用户正在操作的那张图。
- 裁剪结果应记录原图在多图中的 index。

## 9. 裁剪框视觉设计

### 9.1 裁剪框

裁剪框需要明显可见。

建议：

- 边框使用高对比色。
- 边框不要太粗，避免遮挡画面。
- 框内区域保持正常亮度。
- 框外区域加半透明暗色遮罩。

### 9.2 裁剪框外遮罩

遮罩用于告诉用户“只有框内会保留”。

要求：

- 框外图片变暗。
- 框内图片保持清晰。
- 遮罩不应完全挡住图片内容。

### 9.3 九宫格辅助线

裁剪框内部建议显示九宫格辅助线。

用途：

- 帮助用户构图。
- 帮助对齐主体。
- 帮助做三分法裁剪。

视觉要求：

- 两条竖线。
- 两条横线。
- 线条要轻，不要喧宾夺主。

### 9.4 8 个控制点

裁剪框有 8 个控制点：

- 左上。
- 上。
- 右上。
- 右。
- 右下。
- 下。
- 左下。
- 左。

控制点要求：

- 鼠标悬停时 cursor 与方向匹配。
- 控制点可点击区域要比视觉点稍大，方便操作。
- 保存中控制点禁用。

## 10. 裁剪框操作

### 10.1 移动裁剪框

用户按住裁剪框内部并拖动，可以移动裁剪区域。

规则：

- 裁剪框大小不变。
- 裁剪框不能拖出图片边界。
- 到达边界后应停在边界，不应继续移动。
- 移动过程中实时更新裁剪框位置。

### 10.2 缩放裁剪框

用户拖动 8 个控制点，可以改变裁剪区域大小。

规则：

- 拖动角点时，同时改变宽度和高度。
- 拖动边点时，只改变一个方向。
- 裁剪框不能超出图片边界。
- 裁剪框不能小于最小尺寸。
- 拖动过程中实时更新。

### 10.3 最小尺寸

裁剪框必须有最小尺寸。

建议：

- 裁剪框宽度不小于图片展示区域的 6%。
- 裁剪框高度不小于图片展示区域的 6%。

目的：

- 避免用户裁出 1px 的无意义图片。
- 避免拖拽点重叠。

### 10.4 边界吸附

基础版本不要求磁吸。

后续可以考虑：

- 靠近图片边缘时吸附。
- 靠近中心线时吸附。
- 靠近三分线时吸附。

一期只要保证不超出边界即可。

## 11. 宽高比

### 11.1 宽高比入口

裁剪专用工具栏中有“宽高比”按钮。

点击后打开宽高比菜单。

### 11.2 宽高比选项

建议提供：

| 选项 | 含义 |
| --- | --- |
| 自由 | 用户可以任意调整宽高 |
| 原图 | 裁剪框保持原图片比例 |
| 1:1 | 正方形 |
| 3:4 | 竖版图片常用 |
| 4:3 | 横版图片常用 |
| 9:16 | 竖版视频、短视频封面 |
| 16:9 | 横版视频封面 |

### 11.3 选择比例后的行为

用户选择固定比例后：

- 当前裁剪框会自动适配该比例。
- 裁剪框中心尽量保持不变。
- 如果当前裁剪框无法完全适配，系统应在图片边界内自动缩小。
- 后续拖动控制点时，保持固定比例。

### 11.4 自由比例

选择“自由”后：

- 拖动任何控制点都不再锁定比例。
- 用户可以任意调整宽高。

### 11.5 原图比例

选择“原图”后：

- 裁剪框比例与当前图片显示方向一致。
- 如果图片曾被旋转，需要按旋转后的宽高计算。

## 12. 重置

### 12.1 重置入口

裁剪工具栏中提供“重置”按钮。

### 12.2 重置行为

点击重置后：

- 裁剪框恢复为默认裁剪区域。
- 如果当前选择了固定比例，重置后的裁剪框仍保持该比例。
- 不改变当前宽高比选项。
- 不退出裁剪模式。

### 12.3 重置不需要确认

重置只影响当前编辑草稿，不会修改原图，也不会保存结果，因此不需要二次确认。

## 13. 取消

### 13.1 取消入口

裁剪工具栏中提供“取消”按钮。

也可以支持：

- 按 Escape 取消。
- 点击画布空白处取消，具体由产品决定。

### 13.2 取消行为

点击取消后：

- 退出裁剪模式。
- 不生成图片。
- 不修改原图。
- 普通图片工具栏恢复。
- 丢弃本次裁剪草稿。

### 13.3 保存中不能取消

保存中不建议允许取消。

原因：

- 图片可能已经上传。
- 节点可能正在创建。
- 强行取消会造成状态不一致。

## 14. 保存

### 14.1 保存入口

裁剪工具栏中提供“保存”按钮。

### 14.2 保存流程

点击保存后：

1. 禁用裁剪工具栏。
2. 读取原图。
3. 根据裁剪框计算原图像素区域。
4. 使用 canvas 裁出图片。
5. 导出 PNG 文件。
6. 上传裁剪结果图片。
7. 创建新的图片节点。
8. 原节点和新节点自动连线。
9. 退出裁剪模式。
10. 新图片节点进入选中态。

### 14.3 保存中状态

保存中需要展示：

- 保存按钮变成“保存中”。
- loading 图标。
- 其他按钮禁用。
- 裁剪框不能再拖动。

### 14.4 保存成功

保存成功后：

- 退出裁剪态。
- 显示新图片节点。
- 新节点标题为“裁剪结果”。
- 原图保留。

是否需要 toast：

- 如果新节点自动出现且选中，可以不额外 toast。
- 如果生成位置离当前视图较远，建议轻提示“已生成裁剪结果”。

### 14.5 保存失败

保存失败后：

- 保持裁剪模式。
- 裁剪框草稿不丢失。
- 工具栏显示错误提示。
- 保存按钮恢复可点击。

用户可以：

- 调整后重新保存。
- 直接取消退出。

## 15. 输出结果规则

### 15.1 默认生成新节点

裁剪结果默认生成新图片节点，不覆盖原图。

原因：

- 裁剪是不可逆操作。
- 用户可能还需要保留原图继续尝试其他裁剪。
- 生成新节点更符合画布工作流。

### 15.2 新节点位置

新节点建议出现在原图右侧或下游方向。

规则：

- 与原图保持合理间距。
- 不完全重叠。
- 连续裁剪多次时可以向下错开。

### 15.3 新节点标题

默认标题：

```text
裁剪结果
```

如果是多图中的某一张裁剪，可选标题：

```text
裁剪结果 1
```

### 15.4 新节点内容

新节点保存：

- 裁剪结果图片 URL。
- 图片宽度。
- 图片高度。
- 图片比例。
- 来源图片 URL。
- 来源节点 ID。
- 来源图片 index。
- 裁剪区域。
- 图片来源标识：crop。

### 15.5 自动连线

建议自动创建连线：

- source：原图片节点。
- target：裁剪结果节点。

意义：

- 用户能看到结果来源。
- 下游追溯更清楚。
- 后续导出工作流时能保留加工链路。

## 16. 多图节点裁剪规则

### 16.1 收起态

如果多图节点处于收起态：

- 默认裁剪封面图。
- 裁剪结果来源 index 为封面 index。

### 16.2 展开态

如果多图节点展开，且用户对其中某一张图片点击裁剪：

- 裁剪该张图片。
- 不影响其他图片。
- 裁剪结果仍生成一个新的图片节点。

### 16.3 设为封面后的裁剪

如果用户先把某张图设为封面，再在收起态裁剪：

- 裁剪封面图。
- 下游默认仍读取原节点封面，不会因为裁剪结果自动替换原节点封面。

## 17. 数据结构建议

裁剪结果节点建议保存：

```json
{
  "type": "result",
  "data": {
    "label": "裁剪结果",
    "resultType": "generateImage",
    "imageUrl": "裁剪结果图片地址",
    "imageUrls": ["裁剪结果图片地址"],
    "imageSource": "crop",
    "imageSize": "16:9",
    "imageDimensions": {
      "width": 1280,
      "height": 720
    },
    "sourceImageUrl": "原图地址",
    "sourceImageNodeId": "来源节点 ID",
    "sourceImageIndex": 0,
    "cropRegion": {
      "x": 0.12,
      "y": 0.18,
      "width": 0.76,
      "height": 0.5
    }
  }
}
```

字段说明：

| 字段 | 说明 |
| --- | --- |
| imageSource | 固定为 crop，表示图片来自裁剪 |
| imageSize | 裁剪结果比例或尺寸展示 |
| imageDimensions | 裁剪结果真实像素宽高 |
| sourceImageUrl | 原始图片地址 |
| sourceImageNodeId | 来源节点 ID |
| sourceImageIndex | 多图节点中的图片序号 |
| cropRegion | 归一化裁剪区域 |

## 18. 裁剪坐标规则

### 18.1 使用归一化坐标

裁剪框建议使用归一化坐标保存。

也就是：

- x 范围是 0 到 1。
- y 范围是 0 到 1。
- width 范围是 0 到 1。
- height 范围是 0 到 1。

示例：

```json
{
  "x": 0.12,
  "y": 0.12,
  "width": 0.76,
  "height": 0.76
}
```

好处：

- 不受节点在画布上的显示尺寸影响。
- 画布缩放后仍然准确。
- 图片节点变大变小时，裁剪区域不丢。

### 18.2 转换为像素坐标

保存时需要把归一化坐标转换为原图像素坐标。

公式：

```text
pixelX = crop.x * imageWidth
pixelY = crop.y * imageHeight
pixelWidth = crop.width * imageWidth
pixelHeight = crop.height * imageHeight
```

需要注意：

- x 和 y 建议向下取整。
- width 和 height 建议四舍五入。
- 结果不能超出图片边界。
- 最小宽高不能小于 1px。

## 19. 技术实现方案

### 19.1 前端裁剪方案

基础方案：

1. 加载原图。
2. 创建 canvas。
3. 根据裁剪框计算像素区域。
4. 使用 `drawImage` 裁出指定区域。
5. 使用 `canvas.toBlob()` 导出 PNG。
6. 上传 PNG。
7. 创建图片节点。

### 19.2 图片读取

图片可能来自：

- 本地上传后的 `/uploads/` 地址。
- 同源地址。
- 第三方图片地址。
- data URL。
- blob URL。

处理要求：

- data URL 和 blob URL 可以直接加载。
- 同源图片可以直接 fetch。
- 跨域图片需要走代理下载或后端转存。
- 如果图片无法读取，需要给用户明确提示。

### 19.3 跨域问题

浏览器中，图片画到 canvas 后，如果图片跨域权限不正确，会导致 canvas 无法导出。

用户能看到图片，不代表一定能裁剪。

开发需要确认：

- 图片服务是否允许跨域读取。
- 是否需要同源代理。
- OSS / CDN 是否配置 CORS。
- 是否有后端下载代理兜底。

### 19.4 输出格式

一期建议输出 PNG。

原因：

- 质量稳定。
- 支持透明通道。
- 实现简单。

后续可以支持：

- JPG。
- WEBP。
- 保持原格式。

### 19.5 大图性能

大图裁剪可能消耗内存。

开发需要考虑：

- 超大图片是否限制最大尺寸。
- 是否需要 OffscreenCanvas。
- 是否需要后端裁剪兜底。
- 移动端内存限制。

## 20. 错误场景

### 20.1 图片为空

场景：

- 图片节点没有 imageUrl。

处理：

- 不允许进入裁剪。
- 提示“请先上传图片”。

### 20.2 图片加载失败

场景：

- 图片 URL 失效。
- 图片资源无法访问。

处理：

- 禁用裁剪按钮。
- 或点击后提示“图片读取失败，无法裁剪”。

### 20.3 后端服务未启动

场景：

- 本地 `/uploads/` 图片需要后端服务，但后端没启动。

提示：

```text
本地图片读取失败，请确认后端服务已启动。
```

### 20.4 跨域读取失败

场景：

- 图片可以显示，但 canvas 不能读取。

提示：

```text
图片读取失败，请检查图片跨域配置。
```

面向普通用户可以显示：

```text
当前图片暂时无法裁剪，请重新上传图片后再试。
```

### 20.5 裁剪图片生成失败

场景：

- canvas 导出 blob 失败。

提示：

```text
裁剪图片生成失败，请重试。
```

### 20.6 上传失败

场景：

- 裁剪图片生成成功，但上传文件失败。

处理：

- 保持裁剪编辑态。
- 展示错误。
- 允许重新保存。

### 20.7 创建节点失败

场景：

- 上传成功，但画布创建节点失败。

处理：

- 提示“裁剪结果创建失败，请重试”。
- 不关闭裁剪态，避免用户丢失选择。

## 21. 交互边界

### 21.1 画布拖拽冲突

裁剪编辑态中：

- 拖动裁剪框不能触发画布拖拽。
- 拖动控制点不能触发节点拖拽。
- 裁剪工具栏点击不能选中其他节点。

### 21.2 节点失去选中

如果用户点击画布空白导致节点失去选中：

- 可以自动退出裁剪态。
- 如果正在保存，不应退出。

### 21.3 图片节点被删除

如果裁剪过程中原节点被删除：

- 裁剪态应结束。
- 不创建结果节点。

### 21.4 页面刷新

裁剪草稿属于临时状态。

页面刷新后：

- 不需要恢复裁剪框。
- 不需要恢复裁剪编辑态。

### 21.5 多人协作

一期不需要处理复杂冲突。

后续需要考虑：

- A 用户裁剪时，B 用户删除原节点。
- A 用户裁剪时，B 用户替换了原图。
- 是否需要锁定节点编辑状态。

## 22. 键盘和可访问性

### 22.1 Escape

建议支持：

- 按 Escape 退出裁剪模式。
- 如果宽高比菜单打开，优先关闭菜单。

### 22.2 Tab

工具栏按钮需要支持键盘 Tab 聚焦。

焦点顺序建议：

1. 取消。
2. 宽高比。
3. 重置。
4. 保存。

### 22.3 aria

控制点需要有可访问名称。

例如：

```text
调整裁剪区域 左上
```

### 22.4 键盘微调

一期可以不支持键盘移动裁剪框。

后续可以支持：

- 方向键移动裁剪框。
- Shift + 方向键大步移动。
- Alt/Option + 方向键微调。

设计稿需要包含：

## 24. 开发验收标准

### 24.1 入口

- 图片节点选中后能看到裁剪按钮。
- 空图片节点不展示或禁用裁剪。
- 点击裁剪后进入裁剪态。

### 24.2 裁剪框

- 裁剪框默认在图片内部。
- 拖动裁剪框可以移动。
- 拖动 8 个控制点可以缩放。
- 裁剪框不能超出图片范围。
- 裁剪框不能小于最小尺寸。

### 24.3 宽高比

- 宽高比菜单可以打开和关闭。
- 选择 1:1 后，裁剪框保持正方形。
- 选择 16:9 后，裁剪结果接近 16:9。
- 选择自由后，可以自由调整宽高。
- 重置后仍遵守当前比例。

### 24.4 保存

- 点击保存后生成新图片节点。
- 原图不变。
- 新节点标题为“裁剪结果”。
- 新节点图片内容等于裁剪框内区域。
- 新节点尺寸比例与裁剪结果一致。
- 新节点与原节点连线。

### 24.5 失败处理

- 图片读取失败时有提示。
- 上传失败时保留裁剪框。
- 保存失败后用户可以重试。
- 失败后不会生成空节点。

### 24.6 多图

- 多图展开态可以裁剪指定图片。
- 裁剪结果来源 index 正确。
- 不影响多图节点其他图片。

## 25. 测试用例建议

### 25.1 基础裁剪

- 上传一张 1920x1080 图片。
- 进入裁剪。
- 选择 1:1。
- 保存。
- 检查结果图片宽高接近相等。

### 25.2 边界拖拽

- 将裁剪框拖到最左上。
- 继续往左上拖。
- 裁剪框不应超出图片。

### 25.3 最小尺寸

- 拖动控制点把裁剪框缩到很小。
- 裁剪框应停在最小尺寸。

### 25.4 固定比例缩放

- 选择 16:9。
- 拖动右下角。
- 宽高比例应保持 16:9。

### 25.5 重置

- 修改裁剪框。
- 点击重置。
- 裁剪框恢复默认区域。

### 25.6 取消

- 修改裁剪框。
- 点击取消。
- 不生成新节点。
- 原图不变。

### 25.7 跨域失败

- 使用一个没有 CORS 的远程图片。
- 点击保存。
- 应显示错误，不创建空节点。

### 25.8 上传失败

- 模拟上传接口失败。
- 点击保存。
- 应保留裁剪态，并显示失败信息。

后续可以考虑：

- 支持输出 JPG / PNG / WEBP。

- 支持用同一裁剪区域应用到多张图片。
- 支持后端高性能裁剪。
